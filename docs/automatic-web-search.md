# 通常チャットの自動Web検索

2026-10-15に`codex/automatic-web-search`で追加。配布用の開発版は`artifacts/release-auto-search/Eluna.exe`。SearXNGのサーバーを同梱する方式ではなく、.NET標準機能で作った検索・本文取得を利用する。追加パッケージはない。

## 検索から回答まで

`WebSearchService`がBing RSS、DuckDuckGo Lite、日本語Wikipedia APIへ並列に問い合わせ、URLの重複を除去する。公開HTTP/HTTPSページのHTML・テキストから本文を取り出し、取得日時とURLを保存する。本文内の参照リンクも共通予算の範囲で取得候補へ加える。ローカルのllama.cppで回答を作り、実際に取得した本文と引用の一致を確認して出典を付ける。検索先の制限・失敗、本文の取得失敗は活動へ記録する。Python、Docker、WSL、外部の推論APIは不要。

## 要否の判断

通常の`chat`モードを「チャット · 自動検索」として使う。`SearchRouter`は明示的な検索依頼、新しい情報・URL・出典、環境構築・バージョン・製品のおすすめなどを検索へ進める。挨拶、単純な計算、提供された文章の翻訳・整形などは直接回答する。引用やコードブロック内の検索命令は操作指定として扱わない。

その他は直近の短い会話抜粋をローカルモデルへ渡し、JSONの真偽値で判定する。要否の判定に使う生成は最大32 token・12秒。タイムアウトや不正な結果の場合は検索へ進み、理由を活動へ残す。停止ボタンによる取消では検索へ進まない。自動検索の履歴、取得資料、停止後の再開には既存の調査機能を使う。判断から検索・回答まで実行中の状態を保ち、二重送信やモード変更を防ぐ。

「Web検索 · 必ず」と自然文の「検索して」「検索お願いします」等はモデルの判定を経ず検索を試みる。検索語は質問から直接作るため、計画生成が失敗しても検索開始を妨げない。深掘り調査・ディベートの計画確認は従来どおり。「検索しない」では検索指定を含めてもWebへ問い合わせない。自動検索モードでの「検索しないで」も尊重する。再生成・続きの生成で入力欄のモードを勝手に変えない。

検索サービスへ送る情報と操作は[検索ガイド](research.md)を参照。特に「それの最新情報は？」という追加質問では、直前のユーザーの質問の一部も検索語に含める。

## 検証と限界

`scripts/Verify.ps1`で、自動・強制・検索なしの優先順位、モデル判定、判定失敗時の検索、引用やコードの除外、追加質問の文脈、取消、履歴の互換性を含む回帰検証を実行した。結果は`artifacts/automatic-web-verify.log`。

Qwen3.5-4Bの実モデルでは、一般的な説明・創作を検索なしにし、公式情報を求める質問から実検索・本文取得・回答へ進むことを確認した。モデルがWPF環境構築を検索不要と判定する例があったため、環境構築などは判定を経ず検索する規則を加えた。実通信、通常回答、明示依頼、強制モード、検索なし、停止・再生成、保存の確認は`--verify-search-routing`で再現できる。

検索要否や検索の成功は、事実の正確さを保証しない。本文2件に制限した実通信例ではブログ・SNSを取得し、「公式情報」という依頼に対して一次資料以外を根拠に公式と説明する回答も残った。引用の文字列一致は主張の意味の一致を保証しない。検索先の取得制限、ページの解析範囲、モデルによる要否判断と読解の誤りは残る。[既存の調査評価](research-evaluation.md)も参照。

UIはアプリを起動し、WPFの描画で通常・最小サイズと明暗テーマを確認する。実際のIME、高DPI、複数モニター、スクリーンリーダーの確認は今回も未実施。
