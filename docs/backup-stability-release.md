## 実装

全体ZIPの保存対象・操作・制約は[バックアップの仕様](backup.md)を参照。履歴だけの世代バックアップを残し、全体ZIPを別の形式として追加した。通常終了後の復元と再起動を主画面の終了経路へ組み込み、古いプロセスが復元後のファイルを保存し直すことを避ける。キャンセル・破損・検証失敗は現在のデータを保持し、ファイル切り替え中の中断は起動前に戻す。

ダウンロード一覧は完了記録だけでなく、モデル情報と本体の存在・容量を確認して復元する。本体を含めなかったバックアップの復元や手動削除でモデルがなくなった場合も再取得できる。外部モデル保存先とデータフォルダー内のモデルを区別し、復元で元の外部フォルダーへ書き込まない。

既存スキルの取消テストで、PowerShellがマーカーを書いている途中に読み取りが競合する問題を修正した。書き込みを閉じてからマーカー名へ切り替えるため、ファイルの存在で読み取り可能な状態を判定できる。

履歴保存の進行中に届く保存要求は次の最新スナップショットへまとめ、要求ごとに全履歴を保存待ちのメモリへ積まないようにした。各呼び出しは自分の変更を含む保存の完了を待つ。ファイルを一時的に置き換え不可にした状態で300件を要求し、全呼び出しの完了後に最後の変更がディスクへ残ることを検証する。バックアップ開始前と通常終了時も保存の完了を待つ。

## 検証

- `BackupChecks`: スキル本体・生成物・予約・下書き・メモリ・読書位置を別の保存先へ復元。本文中のパスを保持し、出力先・スキル生成物の参照を付け替える。モデルなし／外部モデル込み、既存ZIPを保つ取消、破損・不正パス、切り替え途中の失敗と起動時の巻き戻しを検査する。
- `QueueStabilityChecks`: 同時数1〜4で合計960件。同じ会話の順序、繰り返しの投入・取消、メモリ不足とエンジン終了を模擬した例外の分離、終了時の後始末を確認する。実VRAMを枯渇させる試験とは区別する。
- `--verify-backup <記録先> --model-meta <model.json>`: 設定画面の明暗テーマ・最小サイズ・文字130%、編集停止と解除、ViewModelを通した保存・別保存先への復元を確認。実モデルがある場合は文書4並列・画像モデル不在の失敗分離、チャット4並列と個別停止を確認する。`--stress-seconds 600`で10分間の反復を追加できる。
- `--verify-restore-cycle <記録先>`: 主画面の通常終了、データ切り替え、新しいプロセスの起動までを通して確認。再起動後の会話・未送信下書き・生成文書・出力先と、未完了予約が再開待ちになり自動実行しないことを検査する。
- `scripts/Test-AppRecovery.ps1`: 専用に起動したアプリをストリーム保存後に強制終了し、子エンジンの終了と新しい起動での本文復元を確認する。履歴の保存版1〜3を検出するよう更新した。
