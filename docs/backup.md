# 全体バックアップと復元

設定 → 管理 →「データ・バックアップ」の「全体バックアップ」からZIPを作成・復元する。従来の履歴JSONの書き出し・取り込み・20世代の自動保存と診断は、同じ画面の「履歴JSON・診断」へ分けている。

## 保存するもの

Computer Useの依頼・追加指示・計画・操作履歴・入力文字・結果も会話に含まれます。スクリーンショットやアプリの操作許可は含めません。復元後は自動操作せず、最新画面の確認とアプリの再許可から再開します。

会話と分岐・未送信の下書き・添付、プロジェクトの指示・資料・メモリ、共通メモリ、スキルの登録と各版のファイル、生成文書・画像・スキルの生成物、文書下書き、チャットと画像／文書の予約、ダウンロード一覧、設定、読書位置、主画面の位置を保存する。画像や資料の本文は現在の保存形式と同じく履歴内にも含まれる。

画面には対象ファイル数と圧縮前の容量を表示する。モデル本体は既定で含めない。「モデル本体・画像入力の補助モデルも含める」で会話・画像生成のモデルとprojectorも同梱できる。設定したモデル保存先がデータフォルダー外でも対象となり、モデル情報から参照する外部の補助モデルや、選択した外部の画像生成モデルも含める。

再展開できる実行エンジン、通信の一時鍵、取得途中の`.part`、保存途中の`.tmp` / `.writing`、既存のバックアップ・復元作業領域は対象外。モデルの選択・名前・お気に入り・設定等は本体を含めない場合も保存する。元のPCにしかない外部モデルは、本体を含めたバックアップで移すか、復元先で再取得・追加する必要がある。

推論・生成・モデル管理の実行中には作成／復元を開始しない。停止・完了後に実行する。ダウンロードは一時停止し、チャットとメディアの予約は保存する。アーカイブの作成中は画面の編集と新規実行を保留する。中止・失敗時は保存済みのZIPを置き換えない。ウィンドウを閉じる操作では中止と後始末を待つ。

## 復元

1. 「ZIPから全体を復元」でZIPを選び、作成日時・ファイル数・容量を確認する。
2. 現在のデータを置き換えて再起動することを確認すると、別の作業領域へ展開し、一覧・容量・SHA-256・データ形式を検査する。この段階では現在のデータを変更しない。
3. 編集中の他画面を通常の保存／破棄確認で閉じる。キャンセルした場合は復元しない。
4. アプリの通常の保存とエンジン停止を済ませ、復元前の全体バックアップを`Backups/before-restore-日時-ID.zip`へ保存する。モデル本体を置き換える復元では、退避側にも現在のモデル本体を含める。
5. 復元記録をディスクへ書いてから対象ファイルを切り替え、アプリを再起動する。途中で失敗した場合は元へ戻す。切り替え途中で強制終了した場合も、次の起動で復元記録から元へ戻してから履歴を読む。

復元後の未完了の推論・生成・ダウンロードは、自動実行せず再開待ちとする。モデル本体がないダウンロードも再開待ちへ戻し、再取得できる。予約内のモデルや出力先、スキル生成物の参照は復元先へ付け替える。会話本文に書かれたパス文字列は書き換えない。存在する外部モデルを本体なしで引き継ぐ場合は参照を保持し、外部モデルが見つからない場合は復元先の標準モデルフォルダーを参照する。

モデルの保存情報は復元先のデータフォルダー内の`Models`へまとめる。存在する外部モデル本体への参照は利用できるが、モデル管理画面で指定していた外部フォルダーを復元先の書き込み先として自動採用しない。

「退避先を開く」で復元前のZIPを確認できる。元に戻す場合も同じ「ZIPから全体を復元」を使う。復元前ZIPと`restore-previous-*`の退避ファイルは自動削除しないため、内容を確認して不要な世代を整理する。従来の履歴JSONの自動保存は20世代で、全体ZIPの定期自動作成とは別の機能。

## 形式と上限

ZIP内の`manifest.json`に版1、作成日時、元の保存先、モデル同梱の有無、ファイルごとの容量とSHA-256を記録する。本文は`files/`以下へ置く。最大100,000ファイル・展開後1 TB、一覧16 MB、各ルート管理JSON 256 MB、モデル情報JSON 2 MB。展開前に空き容量も確認する。モデル込みの復元は、展開先と復元前の退避にも空き容量が必要。

不正パス・重複名・予約デバイス名・対応外の保存先・ZIP内のリンク・保存元／復元先のジャンクション等を拒否する。破損したバックアップや対応していない版で現在のデータを上書きしない。SHA-256は破損の検出用であり、バックアップは暗号化・署名されない。会話や資料等を含む本人のデータとして管理する。

実装・動作確認・配布とGitの記録は[バックアップと安定性の作業記録](backup-stability-release.md)を参照。
