## 予約・保存の扱い

画像・文書の生成ボタンは、画面の入力内容を固定して処理リストへ登録する。同じ画面から次の依頼を追加でき、画面には最後に選んだ依頼の出力を表示する。他の依頼の出力は専用ファイルへ保存し、処理リストの「開く」から確認・コピー保存できる。生成画面を閉じても登録済みの依頼は続行する。補助ファイルの設定等の準備処理は、従来どおり画面を閉じると取り消す。

保存先は`media-jobs.json`、生成物は`Generated/Jobs/`。予約はファイルへ保存してから開始する。再開は保存した依頼を最初から実行する。スキルの補助コードも再実行される場合があり、その時点の実行許可・失効を確認する。本文の途中経過は間引いて保存し、通常終了時は最終状態を保存する。異常終了時は最後の保存時点まで復元する。

保存する参照情報は、予約時に選んだ範囲の指示と抜粋へまとめる。各予約へ全履歴を複製しない。参照範囲の外の会話・資料を混ぜず、後から資料を編集しても予約済みの抜粋を差し替えない。実行・再開待ちの依頼が参照するモデルやプロジェクトの削除・保存先移動、バックアップ復元を保護する。

ダウンロードの保存先は`downloads-v2.json`。従来の`downloads.json`を読み込める。画像モデルの依頼を旧版が会話モデルとして扱わないよう、新しい保存先へ書く。再起動時は未完了の取得を一時停止して復元する。画像モデルもSHA-256検証後に利用可能にする。取得・生成の同時実行数の初期値は各1で、設定は保存される。

予約ファイルには依頼・資料の抜粋等の私的な情報を含む。モデルの重みとともにGitへ追加しない。現在の履歴JSONの書き出し・世代バックアップには画像／文書の予約ファイルを含めない。その後、[全体ZIPバックアップ](backup.md)を追加し、予約・生成物・スキル本体もまとめて保存・復元できるようにした。保存先全体を退避する場合は`media-jobs.json`、`Generated/`、`Skills/`等も保持する。

## 制約と未確認条件

空きVRAMはOSの計測値であり、利用可能量の保証ではない。カウンター未対応、GPU名を一意に対応付けられない場合は不明と表示する。内蔵GPUはRAMと共有する。必要量予測にはモデル構造・バックエンド・解像度による誤差があり、現在の空き容量にはすでに実行中の使用分が含まれる。予測値を単純に減算して正確な残量とは扱わない。

能力フィルターは配布情報の有無を扱い、実際の能力・精度を認定しない。SD 1.4 / SD 2.1は配布情報と対応形式を確認した候補で、今回の実生成は未確認。SDXL・FLUX等の分離構成、画像編集等の従来の対応範囲は変更していない。projectorの設定等の準備操作は排他で行い、生成の並列枠へは混ぜない。

長い単一ブロックは末尾の更新対象として再解析される。解析を背景へ移しても、WPFの組版・描画の費用がなくなるわけではない。長時間・巨大回答の入力遅延を網羅した性能保証は行わない。実モデル4件同時、各社GPU、メモリ不足が続く条件、物理IME・全画面のキー巡回、スクリーンリーダー、実OSのハイコントラスト、150% / 200% DPIと複数モニターは未確認。

実装時のAPI確認には、Microsoftの[PDH配列取得](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw)、[DXGIのGPU識別情報](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ns-dxgi-dxgi_adapter_desc1)、[DXGIのプロセス別メモリ予算](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiadapter3-queryvideomemoryinfo)、Hugging Faceの[モデルカードのメタデータ仕様](https://huggingface.co/docs/hub/model-cards)を参照した。DXGIのプロセス使用量をGPU全体の使用量として扱わない。
