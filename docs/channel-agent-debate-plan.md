# チャンネル・エージェント・自由形ディベートの統合改修計画

作成日: 2026-10-16。状態: A01〜A16を実装。採用した保存方式・実際の上限・操作・検証範囲は[実装記録](workspaces.md)を参照。以下は合意した改修計画として保持する。

これまでの相談で採用した方向をまとめる。通常チャット、既存のラウンド制ディベート、自由形ディベートを、エージェントが参加する共通のチャンネル／DMと発言表示へ統合する。数値の初期値や内部の型名は実装前の仮案とする。

## 1. 目指す使い方

- 利用者はプロジェクトをサーバーのような作業領域として作り、その中へ用途別のチャンネルを作成する。
- 特定のAIエージェントとのDM、複数エージェントとのグループDMも使える。
- 通常会話、複数AIへの相談、ラウンド制／自由形式の議論を同じ会話表示で扱う。
- エージェントは固有のアカウントを持ち、使用モデルが変わっても人格設定と履歴の同一性を保つ。
- 参加した会話を保存し、許可された過去の履歴・メモリから必要な内容を参照する。別のサーバーへ参加した際にも、持ち越しを許可した内容を利用できる。
- サーバーはPC内の作業領域。Windows専用・C# / WPF・ローカル推論・単体exe配布を維持する。

## 3. エージェントと履歴の扱い

- エージェント、サーバー、チャンネル、スレッド、発言に安定した識別子を持たせる。表示名を関連付けのキーにしない。
- 発言は話者IDに加え、その時点の名前・モデル・役割等を保持する。プロフィールやモデルの変更によって過去の表示を別人の発言へ書き換えない。
- 同じモデルを使う別エージェントは別の履歴・記憶を持つ。同じモデルであることだけを理由に履歴を統合しない。
- 過去の全会話を保存対象とする。回答時は参照可能な履歴から検索・抜粋・要約して入力枠へ収める。全履歴を毎回モデルへ渡す仕様ではない。
- 部分生成は未完了として保存し、確定済み発言と区別する。中断された発言を確認なしで確定した主張として扱わない。
- エージェントの退席・無効化後も過去の発言を表示できる。アカウントや履歴を削除する際は対象範囲を明示する。
- モデル未取得・削除・使用不能の場合は対象エージェントを明示して案内する。別モデルへの変更は利用者が選ぶ。

## 4. 記憶とサーバーの境界

保存先、参照する権限、今回回答へ渡した抜粋をそれぞれ管理する。

| 情報 | 初期の参照範囲 | 持ち越し |
| --- | --- | --- |
| エージェントの基本プロフィール | そのエージェントが参加する場所 | 共通の人格設定として使う。場所固有の事実を自動で基本指示へ組み込まない。 |
| チャンネルの会話 | そのチャンネルと関連スレッド | 別チャンネルへの参照は設定または明示引用。別サーバーへの持ち越しも許可範囲に従う。 |
| サーバーの資料・限定メモリ | そのサーバー | 既存のプロジェクト限定の境界を維持する。 |
| エージェントが持ち越す履歴・保存メモリ | 利用者が指定した共有範囲 | 出所側の共有設定と移動先の受け入れ設定の両方を満たす場合に使う。 |
| DM／グループDMの内容 | そのDM | 個別に許可した内容を持ち越せる。参加していないエージェントへ自動共有しない。 |

- 新しい限定サーバーは外部の履歴・記憶の受け入れを初期オフとする。既存サーバー相当の設定は移行時に保持し、自動で範囲を広げない。
- 既存の共通指示・共通メモリの利用条件も維持する。新しいエージェント機能を経由して限定範囲を回避しない。
- 同じ場所の共有資料や発言と、参加者ごとの記憶を区別する。ある参加者に渡した個人の記憶を、ほかの参加者の入力へ自動複製しない。
- 回答に使った会話・資料・メモリの出所を表示する。履歴・メモリの検索結果には場所と対象エージェントの条件を適用する。
- 「保存メモリへの追加」は内容と範囲を利用者が確認する。無断の自動追加を行わない。
- 削除・無効化した情報は今後の検索対象から外し、派生した検索索引や要約も必要な範囲で無効化する。過去の回答に引用済みの内容やバックアップに残る内容の範囲は説明する。
- 予約済みの処理が保持する抜粋は明示する。範囲の変更・共有の取り消し時には、該当する予約を停止して再確認できる仕組みを設ける。

## 5. チャンネルと中央チャットのUI

- 左端: プロジェクト／サーバーの選択とDMへの入口。
- 左側: チャンネル、DM、グループDM、作成と保管の操作。通常チャットもこの構成へ移す。
- 中央上部: 場所名、参加者、参照範囲、会話／議論の状態。
- 中央本文: 利用者と各AIの発言を名前・アイコン付きで時系列に表示。司会の整理も一つの投稿として表示する。
- 入力欄: 宛先、思考量、通常会話／議論の進行操作、添付。議論中は議論への追加発言であることを明示する。
- 必要時の詳細欄: 参加者、資料、参照した記憶、スレッド。狭い画面では開閉して会話幅を確保する。
- ラウンド制はラウンドの区切りを控えめに表示。自由形式は返信関係と現在の論点を表示する。
- 行の補助操作はホバー／キーボードフォーカス時に表示し、長文・コード・引用・添付の読みやすさと一度に見える情報量を保つ。
- 推論中に別の場所を開いた場合も発言を正しい場所へ追記し、入力中の下書きと読書位置を保持する。

## 6. 自由形ディベートの進行

1. 議題、AI参加者、進行役、検索方針、生成上限を設定して開始する。参加者の既存ドラッグ＆ドロップ操作を再利用する。
2. 進行役が現在の論点・未回答の質問・反論先・発言の偏りから次の発言者を選ぶ。利用者の指名を反映する。
3. 選ばれた参加者へ、許可された資料・記憶、最近の発言、以前の議論の要約を渡す。
4. 参加者の発言を中央へストリーム表示し、確定後に返信関係と論点を更新する。
5. 必要なら追加調査、利用者への質問、途中整理を行う。合意点と未解決点を引き継いで次の発言へ進む。
6. 利用者の終了指示、設定上限、議論の区切りでまとめを作る。合意が得られない場合は相違点を残す。

進行上の条件:

- 自動進行と、一発言ずつ進める手動進行を用意する。
- 初期は発言するAIを2〜6名とし、利用者も途中参加できる。司会役は参加者との兼任を可能にする。
- 通常の追加指示は現在の発言が終わったところで適用する。「割り込む」は生成を中断し、最新の指示から再判断する。
- 途中の参加者追加・退出・役割／モデル変更も発言の区切りで反映し、変更前の履歴と進行中の入力を保持する。
- 発言者の独占、同じ内容の反復、未回答の放置を抑える。対象IDや進行指示が不正な生成結果は入力検証し、再試行を有限にして手動進行へ切り替えられるようにする。
- 各回すべてのAIへ発言希望を問い合わせる方式は初期実装では採用せず、進行判断の推論回数を抑える。
- 初期の数値案は12発言・10分・全工程12,000 token。司会・検索語・要約も同じ予算へ含め、最終整理の枠を確保する。実モデルの速度と議論の長さから調整する。
- 一致した人数だけで事実の正しさを決めない。事実・提案・推測・未確認を区別し、引用には取得済み資料を対応させる。

## 7. 検索・推論・既存機能

- ラウンド制は既存の役割・順番・ラウンド数と調査処理を引き継ぎ、自由形式は発言順を動的に決める。両者で発言表示・停止・保存を共通化する。
- 検索は自動／必ず／使わないを選択できる。明示的な検索依頼は検索を試み、失敗・本文未取得は活動に残す。
- 議論中の追加検索は重複を除去し、許可された同じ場所の参加者へ資料を共有する。Web資料とローカルの記憶の出所を区別する。
- まずは一つの議論で一人ずつ推論し、モデル切り替えと待ち時間を表示する。エージェント数とモデルの同時常駐数を同一視しない。
- 別チャンネルや通常の生成は既存の推論キューと同時実行数の設定に従う。資源不足で全体のUIを停止させない。
- 画像／文書生成、深掘り調査、スキル、Computer Useの既存経路を、新しい場所・依頼・エージェントへ関連付ける。
- エージェントのアカウントを作るだけで、スキルのコード実行やComputer Useのアプリ操作の許可を与えない。従来の許可・停止条件を適用する。
- 全タスクへスリープ抑止を広げる変更は今回の必須範囲としない。Computer Useの既存設定は保持する。

## 8. 保存・移行

- 新形式の保存データに識別子、所属、参加者、発言と返信、参照範囲、議論の進行状態を保持する。形式番号・ファイル名は実装前に既存保存方式との整合を確認して決める。
- 既存データを退避し、旧ファイルを保持して移行する。途中で失敗した場合は旧データで起動できるようにする。
- 旧プロジェクトは対応する作業領域へ、旧会話はその中の移行済みチャンネルへ対応付ける。所属のない会話も「移行した会話」として全件アクセス可能にする。既存会話を一つのDMへ自動結合しない。
- 旧発言の不明な時刻・モデル・話者は捏造しない。移行用の話者識別子と既存の情報を使い、表示名だけで別の役割やエージェントを統合しない。
- 旧分岐の全履歴と選択状態を保持する。スレッドとの対応は、本文や参照先を失わない移行手順として実装する。
- 既存の議論は発言を一度だけ中央へ表示し、活動・資料・検証・最終まとめを参照できるようにする。過去の参加者を新しいモデルへ勝手に割り当てない。
- 再起動時は中断した生成・議論を再開待ちにする。確定済みの発言を再生成せず、未完了の発言と残り予算を表示する。
- 全体ZIPバックアップ、履歴の書き出し・取り込み、IDの再割り当て、破損回復を新しい参照関係へ対応させる。別アカウント／別サーバーの取り込みを名前だけで統合しない。

## 10. 完了条件

- 同じエージェントがDMと複数の作業領域へ参加し、許可した過去の内容を使える。許可のないサーバー・DM・別エージェントの記憶は入力へ混入しない。
- モデル・名前・役割を変更しても発言の帰属と過去の表示が保たれる。エージェントを退出させても履歴が読める。
- 通常チャットとラウンド制・自由形式の全参加者の発言が、中央へ一度ずつ表示される。生成途中の発言も正しい場所と話者へ結び付く。
- 自由形式で反論・指名質問・利用者の途中発言・割り込み・参加者入替・追加検索・終了まで実モデルで確認できる。
- 停止・エラー・上限・再起動・会話の切り替えでUIが操作でき、下書きと読書位置が保たれ、確定済み発言が再送されない。
- 旧データの移行と新形式のバックアップ復元で、会話・分岐・添付・資料・記憶・議論・生成物とその関連付けが失われない。
- 長い履歴は必要な範囲を取得して表示し、入力はモデルの上限へ収める。日本語IME、キーボード操作、最小サイズ、明暗テーマ、文字拡大、DPI、長文の確認条件を記録する。
- C#は`./scripts/Verify.ps1`、UIは起動・描画・操作、配布は`./scripts/Publish.ps1`と単独exeの起動・同梱エンジンの展開／起動を確認する。未実施の実機条件を区別する。
- 外部パッケージ追加は想定しない。必要と判明した場合は既存の開発ルールに従って追加前に相談する。

## 11. 追加候補との対応

以前提示したD01〜D07のすべてを必須採用した扱いにはしない。今回の構成に必要な部分と、追加候補を分ける。

| 候補 | 今回との関係 |
| --- | --- |
| D01 発言からのスレッド | A08へ含める。 |
| D02 メンション | A09と自由形ディベートの指名へ含める。 |
| D03 採用・保留・要検証の判断マーク | 追加候補。自由形式で発言する際の「保留」と、利用者が投稿へ付ける判断マークは別機能。 |
| D04 作業・生成物カード | A13で既存の進捗・結果を発言へ関連付ける。カード操作やギャラリーの大幅な拡張は追加候補。 |
| D05 未読・呼びかけの表示 | 追加候補。読書位置と下書きの保持は今回も維持する。 |
| D06 発言リンク・ピン留め | 返信元への移動はA08へ含める。ピン留め・決定事項一覧は追加候補。 |
| D07 発言の絞り込み | 参加者・出典・生成物による専用フィルターは追加候補。履歴と記憶の検索は今回の対象。 |

人間同士のオンライン共同利用、外部Discordとの接続、クラウドのアカウント同期、音声通話、複数PC間のエージェント同期も、この改修計画の必須範囲には含めない。
