# 画像とドキュメント（開発版）

2026-10-15、`codex/media-documents`で追加。配布用exeは`artifacts/release-media/Eluna.exe`。C# / WPFと標準.NET / Windows機能を使い、承認済みのstable-diffusion.cpp以外のパッケージを追加していない。モデルの重みはexeに含めず、GUIで取得・選択する。

## 添付・認識

入力欄の「＋」→「画像・文書を添付…」を使う。ファイルを会話へドロップする方法と、クリップボードの画像・ファイルを入力欄へ貼り付ける方法もある。チップで内容を確認・削除して質問を送信する。添付だけ送信すると内容の説明を依頼する。下書き・会話・分岐・履歴のJSON入出力にも添付を保存する。

画像/PDFには、画像入力を扱える会話モデルと、そのモデルと同系列・同サイズのmmproj GGUFが必要。「＋」→「画像認識モデルの設定…」で、選択中モデルのリポジトリからprojectorを探して取得するか、手元のGGUFを追加する。SHA-256を確認して管理フォルダへ保存し、llama.cppを`--mmproj`付きで起動する。別系列のprojectorとの組合せは保証しない。設定後に会話モデルが変わった場合は設定画面を開き直す。

| 入力 | 読み取り方法・範囲 |
| --- | --- |
| PNG/JPEG/BMP/TIFF | 長辺最大1280pxのJPEGへ変換し、ローカルの画像モデルへ渡す。小さい画像は拡大しない。透過部は白に合成。元の画像ファイルは変更しない |
| PDF | Windows標準のPDF描画でページを画像化し、画像モデルで内容・文字を読む。1ファイル6ページまで。暗号化PDFは対象外 |
| DOCX | 本文・表のテキスト。画像、ヘッダー/フッター、変更履歴の完全な再現は対象外 |
| XLSX | セル番地と保存済み値。共有文字列・インライン文字列を扱う。各シート先頭2,000行、最大32シート。数式を再計算しない。書式・グラフ・日付表示形式の再現は対象外 |
| PPTX | スライド順に本文テキスト。最大80スライド。図やレイアウトの読み取りは対象外 |
| TXT/MD/CSV/JSON/LOG | UTF-8テキスト（BOMがあれば標準の文字コード判定）。CSVはテキストとして読む |

1ファイル32 MB、PDFページを含めて1回の添付は最大12件。テキストの保存は各文書先頭60,000文字までとし、上限を超えたことを明示する。大きなOfficeアーカイブ・外部実体を含むXMLは拒否する。原文を入力枠へ収められない場合は、質問と一致する箇所や全体の一部を抜粋する。全文を読んだ扱いにはせず、抜粋の表示を付ける。画像も保存用に変換するため、元解像度の細部を完全に保持するものではない。

添付時には一時的に入力長を16,384 token、画像が多い場合は32,768 tokenまで広げる。モデルの既知の学習長にも配慮するが、モデルの上限・GPUメモリ・資料量によって処理できない場合がある。対応モデルを使っても文字・数値を読み違える場合がある。OCR・図の理解は4B以上を推奨する。

## 添付とWeb検索

単なる内容の説明・要約はローカルで読み取る。最新情報や外部の情報による確認が必要な場合は従来の自動検索が働き、明示的な検索指定も利用できる。検索へ進む場合、先に添付をローカルで読み取り、関連する要点を問いへ加えて検索する。読み取り結果は未検証として扱い、誤読の可能性を残す。読み取りに失敗しても、そのことを記録し、入力された質問で検索を続行する。

検索語には添付の読み取り結果を含む場合があるため、外部へ送る情報を入力欄で説明する。ローカルだけで扱う場合は「検索しない」を選ぶ。画像そのものを検索サービスへ送信する処理はない。モデル・projectorの取得や配布元カードの閲覧は別途インターネットを使う。

## 文書生成

「＋」→「ドキュメントを生成…」で目的・読み手を指定し、「AIで作成」を押す。選択中の会話モデルで本文を生成し、Markdownエディターで修正・プレビューできる。「直前の回答を文書にする…」では既存の回答から編集を始める。

DOCX、Markdown、TXT、PDFへ保存できる。DOCXは見出し・段落・表を持つ編集可能な文書。PDFはWPFで組んだページを画像として格納し、日本語の見た目を保つ。画像PDFの文字選択・アクセシビリティ構造・検索可能なテキスト層には未対応。PDFは60ページまで。既存ファイルへは一時ファイルの生成が成功してから置き換える。生成が上限・取消で終わった場合は、そのことを表示して生成済み本文を保持する。作成画面の操作後は下書きを`Generated/document-draft.md`へ保存する。

生成内容の事実正確性、適切な文体、社内様式などはモデルと指定に依存する。Word等での完全なレイアウト互換性は継続確認が必要。

## 画像生成

「＋」→「画像を生成…」で画像生成モデルを指定する。公開GGUFリポジトリを指定してファイル・容量・利用条件を確認し、ダウンロードできる。手元の一体型GGUFも選べる。既定の候補は`second-state/stable-diffusion-v1-5-GGUF`。モデルカードに記載されたCreativeML OpenRAIL-M等の条件はモデルごとに確認する。

英語で説明するとSD 1.5の意図を伝えやすい。日本語の説明をローカルの会話モデルで英語に変換するボタンもある。除外したい内容、解像度、ステップ数、シード、CPU/GPUを指定して生成する。生成時は会話モデルを解放し、メモリを画像生成へ回す。完了画像は`Generated/`にPNGで保存し、別名保存・会話への添付ができる。停止や終了では子エンジンを止め、途中画像を完成品として残さない。

現在のGUIは一体型Stable Diffusionのモデルを対象にする。動作確認はSD 1.5 Q4_0。一体型SDXLはエンジンの対応範囲だが今回の実生成は未確認。FLUX等の分離したテキストエンコーダー・VAE構成、画像編集、動画生成、複数枚の一括生成は未対応。生成画像の品質はモデル・プロンプト・設定による。CPUは遅く、このPCの256px・1ステップの確認でも約40秒を要した。RX 9070 XTの512px・20ステップの1回の確認ではエンジンの生成処理が約5.7秒だった。一般的な性能保証ではない。

## 検証と未確認範囲

`scripts/Verify.ps1`で日本語DOCX・表の読み書き、XLSX/PPTX、XML外部実体の拒否、添付の下書き・分岐・履歴、長文後半の抜粋、不正な画像入力を確認する。`scripts/Build-Llama.ps1`と`Build-Diffusion.ps1`でCPU/Vulkanをビルドする。`Test-LlamaGpu.ps1 -StaticRuntime`では共有DLLのない分離先でGPU演算をCPU参照と比較する。

実モデル確認は`--verify-media <会話モデルのmodel.json> <mmproj.gguf> <画像生成GGUF>`で実行する。4Bモデルで色の識別、PDFの数字、DOCXのコード、文書生成と再読み取り、CPU/GPUの画像生成・取消を確認した。0.8Bモデルは同じ単純画像にred/whiteと異なる回答を返したため、機能が使えることと認識品質は分けて評価する。

UIは起動して通常・最小サイズ、添付、各タブとテーマを描画確認する。実マウスのドラッグ＆ドロップ、実際のクリップボード/IME、高DPI・複数モニター、スクリーンリーダー、メモリ不足の再現、Wordでの実表示は今回未確認。Windows PowerShell/PDF機能が組織のポリシーで利用できない環境ではPDF読み取りも利用できない。利用者へ追加モジュールやOfficeの導入を要求しない。

日本語OCR、複雑な図表、長い資料の認識精度は今回の実モデル検証だけでは評価できていない。画面上の貼り付けイベントはテストデータで確認し、利用者の実際のクリップボードは検証で変更しない。
