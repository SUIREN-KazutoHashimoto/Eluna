# モデルの取得・整理・設定（開発版）

「モデルを探す」で公開GGUFを検索し、「取得キューへ追加」を押します。複数のモデルを順番に取得します。検索画面を閉じても取得が続き、別のモデルでチャットできます。進行中の取得、一時停止、再開・再試行、速度と残り時間は「ダウンロード管理」で確認します。アプリ終了時は中断位置を保存し、次の起動では一時停止した状態で復元します。

配布元の応答や受信が60秒間止まった場合は取得を終了し、キューに再試行の案内を表示します。全体のダウンロード時間ではなく、一回の待機時間を制限します。

分割GGUFはすべての番号がそろったモデルを一つの項目にまとめ、全ファイルを取得・SHA-256検証してから登録します。「手元のGGUFを追加」でも、同じフォルダにある分割ファイルをまとめて追加します。途中ファイルは完成したモデルとして表示しません。

## PCの容量と能力情報

モデル検索では、空きRAM、選択したGPUが報告する容量、モデルの重み容量から動作メモリの目安を表示します。取得済みモデルはGGUFのヘッダーからパラメーター数、構造、量子化、学習時の記憶長、思考形式を読み取ります。KVキャッシュは全層attention・F16で概算するため、ハイブリッド型では過大に見積もる場合があります。作業用メモリも幅を持たせて案内し、動作や速度の保証値として扱いません。

得意分野、日本語や思考対応の説明は「能力・モデルカード」で配布元のREADMEを確認できます。能力の情報がない場合は「不明」「評価情報なし」と表示します。名称だけから日本語や推論の品質を断定しません。

## 整理と保存先

「モデル管理」で名前、お気に入り、使用容量を確認します。名前を変えてもファイル名やIDは変えず、お気に入りをモデル一覧の先頭に置きます。削除では対象モデルのファイルを確認し、保存先の外の参照ファイルは削除しません。再度取得・追加しても設定と名前を保持します。

「保存先を変更・移動」で別ドライブの専用フォルダを選べます。取得キューを一時停止し、重みと途中ファイルをコピーしてSHA-256の一致を確認します。すべてのコピーと管理情報が整ってから参照先を切り替え、元のファイルを片付けます。中断・失敗時は元の保存先を維持します。移動先に違う内容の同名ファイルがある場合は上書きせず停止します。

モデル管理処理中はチャット生成とモデル切替を止めます。移動は入力欄の停止ボタンやEscでも停止できます。外付けドライブなど保存先が利用できない場合もアプリは起動し、会話を保存できます。ドライブを接続するか、管理画面から新しい保存先を選びます。

## モデル別設定

記憶長、温度、Top P、Top K、繰り返し抑制、回答の最大token数、選択した時の思考量を保存できます。記憶長を0にすると全体設定を使います。「標準」「安定」「創作」のプリセットを用意し、変更は次の生成で反映します。思考形式が確認できないモデルでは思考量を速度優先にします。

調査・ディベートでは、使用するモデルの記憶長のうち小さい値を共通の入力上限にして、モデル切替で入力上限を超えないようにします。最終回答以外の短い工程は速度優先で生成します。

## 確認した範囲

`Verify.ps1`でヘッダー解析、容量案内、設定保存、移動中断、元ファイル保持、削除範囲、キュー中断・順次実行・再起動後のRange再開を確認します。実際のQwen3.5 0.8Bで情報取得・8192 token設定・GPU推論・移動後の再読み込みを確認しました。4分割した同モデルの取り込み・GPU推論も確認しています。

実IME、各種DPI、別PC、各社GPUと大規模なモデルライブラリの確認は継続します。アプリ全体の到達点は[実装・検証の台帳](implementation-status.md)を参照してください。
