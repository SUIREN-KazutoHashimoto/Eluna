# プロフィール・サーバー・ボイスチャンネル

2026-10-16、`codex/voice-profile-channels`。外部パッケージは追加せず、WPF、Windows SAPI、既存のllama.cpp / Computer Useを組み合わせた。

## プロフィール

メンバー一覧、発言者の名前・アイコン、設定のアカウントカードからプロフィールを開く。モデル・名前・アイコン・専門分野・指示・読み上げ音声・速度を編集できる。保存後の新しい依頼に適用し、過去の発言者・モデル・記憶を変更しない。モデルや音声が未取得の場合は選び直せる表示を残す。未保存の編集は閉じるときに確認する。履歴・保存メモリもプロフィールから開ける。

## サーバーと知識

旧プロジェクトはそのままサーバーとして使う。ID、資料、指示、保存メモリ、既存チャンネルとの関連を保持し、保存上のProjectId等は互換性のため残す。サーバー名メニューの「サーバー設定・資料・メモリ」から管理する。設定からの入口も残した。

サーバー限定メモリが既定。共通メモリを使う範囲の選択は作成時に固定し、別サーバーの資料は混ぜない。同じサーバーの別チャンネルの参照、およびアカウントの持ち越し記憶の受け入れには、サーバーとチャンネルの双方の許可が必要。サーバー編集時に既存の受け入れ許可が消える問題を修正した。これらの許可変更は対象サーバーの古い予約・実行を停止する。

## 音声とテキスト

1. チャンネル作成で「ボイスチャンネル」を選び、AIアカウントを指定する。
2. チャンネル上部の「参加する」で接続する。接続直後のマイクはミュート。
3. 「マイクをオン」でWindowsの音声認識を開始する。認識確定した発言をチャンネルへ自動送信する。認識結果は選択・コピーできる。
4. 応答は会話に残り、参加中のチャンネルの新しい応答をプロフィールの音声で順番に読み上げる。「読み上げをオフ」で停止できる。
5. 読み上げ中は音声認識を休止して、スピーカーの出力の誤送信を避ける。「割り込んで話す」で読み上げを止め、認識を再開する。自動の同時発話・エコー除去は実装していない。

テキストの入力欄も常時使える。別チャンネルを表示しても音声接続は続き、音声の投稿先、モデル・指示・検索方法・知識の範囲は参加先に固定する。別チャンネルの下書きと選択を変更しない。ボイスチャンネル間は参加を切り替えられ、同時接続は1か所。退出、対象の削除・保管・移動・分岐変更、終了、バックアップの開始時は音声と画面共有を終了する。再起動時はマイク・共有・操作許可を自動復元しない。

音声認識・合成はWindows SAPIでローカル処理する。音声認識エンジン、認識言語、マイク、読み上げ音声はそのPCにあるものを使う。UI言語と一致する認識エンジンを優先し、使ったエンジン名を表示する。利用できない場合は理由を表示し、テキストは使い続けられる。システム設定や言語パックをアプリが変更・取得することはない。通常の入力は最初に列挙されたマイクを使う。デバイス・認識言語の手動選択は未実装。

生のマイク音声は保存せず、確定した文字起こしと返答を会話として保存する。文字起こしに対するWeb検索は通常のチャンネルの検索設定に従う。認識の精度と声の自然さはWindowsのエンジンによる。これはローカルAIとの通話で、人間同士のネットワーク音声通話は追加していない。

APIの参照: [SAPI認識コンテキスト](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms722041(v=vs.85))、[認識イベント](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms722040(v=vs.85))、[非同期読み上げと中断フラグ](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee431843(v=vs.85))。イベントGUIDとDISPIDはWindows SDKのsapi.hも確認した。

## 画面共有とComputer Use

参加先のボイスチャンネルで「画面を共有」からウィンドウを選ぶ。選択した画面のプレビューを約2秒ごとに更新する。プレビュー更新は前面切り替えや操作を行わない。ウィンドウが閉じられた、最小化された、取得できなくなった場合は共有を停止して理由を表示する。モニター全体の共有とシステム音声の共有は未実装。

共有直後は閲覧のみ。共有中にチャンネルへ送る通常の依頼には、その時の画面の読み取りを添付する。画像対応モデルにprojectorを設定している場合は画像も渡し、それ以外はWindowsのUI要素から得たテキストを使う。送信時の読み取りは会話に保存する。共有の連続画像は保存しない。共有開始画面では、会話への保存と検索設定に応じた外部送信を説明する。

「この画面でAIの操作を許可」をオンにすると、そのチャンネルの新しいテキスト／音声の依頼をComputer Useへ渡す。新しい専用ウィンドウは使わず、進行・確認・停止はチャンネル内で扱う。操作対象は選択したウィンドウ。別アプリの追加許可は共有モードでは行わず、必要な場合は共有を切り替える。重要な操作の確認、実行時の表示効果、Ctrl+Alt+Escの停止は既存の仕組みを使う。

操作許可をオフ、共有終了、退出で、その共有から開始したComputer Useをキャンセルする。実行済みの操作は取り消さない。旧来の`@Computer`や設定のComputer Useモードも互換の入口として残す。

## 表示と検証

長い発言者名と時刻・操作ボタンを別の列へ置き、モデル選択の選択文字が矢印へはみ出す表示を抑えた。プロフィールは本文をスクロールし保存ボタンを固定。サーバー設定のボタン列、音声の操作ボタンは狭い幅で折り返す。音声・共有領域は高さを制限してスクロールする。

共有先の選択画面は、最小サイズ・文字130%でも説明文が一覧を押しつぶさない構成にした。チャンネルの連続切り替えでは、古い表示先のスクロール処理を無効にし、再利用されたメッセージ行の高さを測定した後に読書位置を復元する。表示の再構築中の一時的な位置は保存しない。

```powershell
./scripts/Verify.ps1
./scripts/Publish.ps1 -SkipNativeBuild -OutputDirectory artifacts/release-voice
./artifacts/release-voice/Eluna.exe --verify-voice artifacts/voice-portable/voice --data-dir artifacts/voice-portable/voice/data --model-meta <model.json>
```

`VoiceChannelChecks`は音声設定とチャンネル種別の保存・取り込み、範囲外の設定の拒否、サーバー知識の分離を確認する。`--verify-voice`はプロフィールからのモデル変更、未保存編集、サーバーの資料・メモリ・許可の保持、接続・退出・下書き、共有の取得と権限解除、明暗・最小サイズ・文字130%をWPF操作と描画で確認する。Windows合成音声をWAVへ出力し、そのファイルを認識エンジンへ入力することで、日本語の認識イベントからバックグラウンドのボイスチャンネルへの投稿と実モデルの返答まで検証する。利用者のマイクを録音したり、室内へ確認音声を流したりする試験ではない。

実デスクトップのComputer Useは専用の検証アプリだけを対象とする。今回の環境で前面ウィンドウが0となり入力を実行できなかった条件は、`verification.json`の`realDesktopInputUnverified`に記録する。これを実入力成功として扱わない。実マイク・実スピーカーの連続会話、実キー／IME、高DPI・複数モニター、別PC、全言語の認識品質は未確認。

最終確認は `artifacts/voice-verify.log` と `artifacts/voice-portable-final.log`。exeだけを別フォルダーへコピーし、インストール済み.NETを参照しない設定で実行した。追加機能・日本語の合成／認識から実モデルへの応答は `artifacts/voice-portable-final/voice/verification.json`、既存の主画面は `ui/`、資料・検索表示・ディベート等の描画は `preview/`、密度・未保存編集・処理リスト・読書位置・1万会話／10万発言は `regression/`、実モデルの記憶分離・会話・両方式の議論・介入・検索・文書・バックアップは `live/` に記録した。各フォルダーの `result.txt` は成功。上記の実デスクトップ入力の未確認は別途記録している。CPU/Vulkanのllama-server・sd-cliの4エンジンの展開・起動は `native.json`、exeのSHA-256は `exe.json`。
