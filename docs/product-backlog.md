## 27. 内蔵Web検索（自前の検索基盤を採用）

ユーザーが追加を希望した検索基盤。2026-10-15に「SearXNGが難しければ同等の機能を自前で用意して」と代替方式が承認された。Windows専用・利用者はexeを起動するだけ、という配布目標を維持する。通常検索、深掘り調査、ディベートが共通の検索・資料取得機能を使う。

現在の開発では、C# / .NET標準機能でBing RSS、DuckDuckGo Lite、Wikipedia APIを問い合わせる方式を採用する。外部パッケージ・Python・常駐サーバーは追加しない。SearXNGの全エンジン・全形式との互換性を意味しない。実装と検証の到達点は[実装状況](implementation-status.md)、操作は[調査機能ガイド](research.md)を参照する。

- 入力欄で検索を選択し、モデルが必要に応じて検索語を作って問い合わせる。
- 問いを分解し、複数の検索語、言語、検索エンジンで追加検索する。
- 検索結果のタイトル・URL・概要に加え、必要なページ本文を取得する。
- 同じ資料の重複を除き、取得済み資料を再利用する。
- 回答に出典を付け、根拠の箇所と閲覧日時を開けるようにする。
- エンジン単位の失敗、アクセス制限、取得できないページを画面で説明する。
- 検索回数、取得件数、同時取得数、上限時間を設定し、全工程を停止できる。
- 検索・閲覧の進捗と履歴を表示する。検索語が外部検索サービスへ送られることを明示する。

SearXNGのHTTP APIはJSON出力を設定で有効にする必要がある。[公式Search API](https://docs.searxng.org/dev/search_api.html)。

### 参考: SearXNG本体の同梱を再検討する場合

内蔵は、アプリが管理するローカルの別プロセスを同梱・展開する構成を候補とする。ループバックで待ち受け、利用者にPython、Docker、WSLの事前インストールを要求しない配布を目標とする。実現できることはまだ確認していない。

[公式導入手順](https://docs.searxng.org/admin/installation-searxng.html)はPythonを使うLinux環境を案内し、[公式依存一覧](https://github.com/searxng/searxng/blob/master/requirements.txt)にはFlask、lxml、curl_cffiなどがある。Windowsで動くPython・ネイティブ依存・サーバーの構成、必要ならキャッシュ用プロセス、配布サイズ、起動・終了、更新を先に検証する。[SearXNGのLICENSE](https://github.com/searxng/searxng/blob/master/LICENSE)はAGPL v3であり、配布時のライセンス表示とソース提供の扱いを整理する。

SearXNGを機能として採用したいという要望を、依存一式の包括的な導入許可には広げない。具体的な同梱候補・直接および推移依存・バージョン・配布への影響をまとめ、導入前に相談する。Windows同梱が成立しない場合の別サーバー接続は、代替案として相談する。

## 28. 深掘り調査モード

ユーザーが希望したDeepSearch相当の調査機能。検索、資料の読解、追加調査、根拠の照合、レポート作成を一つの作業として扱う。

- 質問から調査計画と確認すべき論点を作る。ユーザーが計画を修正できる。
- 論点ごとに検索し、見つかった情報から不足点を探して追加検索する。
- 一次資料を優先し、発表日・対象時点・情報の食い違いを確認する。
- 検索結果の概要だけを根拠にせず、取得できた本文と主張を対応付ける。
- 確認できた事実、資料からの推測、未確認事項を区別する。
- 出典付きのレポート、比較表、結論と残る疑問を生成する。
- 調査中の進捗、現在の論点、資料一覧を表示する。
- 調査量の設定、停止、途中結果の保存、アプリ再起動後の再開を設計する。
- レポートを履歴に保存し、Markdownで書き出せるようにする。

検索できない、本文を読めない、根拠が足りない場合は、その状態を結果に残す。調査量を増やしただけで品質が向上したと説明せず、出典の正確さと論点の網羅性を評価する。

## 29. マルチエージェントディベート

ユーザーが希望した複数のエージェントによる議論機能。

- 提案役、批判役、検証役、司会など、役割ごとの会話を作る。
- 同じ論点について各役が案を出し、他の案への反論・検証を行う。
- エージェントが共通のSearXNG検索・資料取得機能を使い、根拠を共有する。
- 司会が合意点、意見の相違、未解決の論点を整理して最終回答を作る。
- 役割、参加数、ラウンド数、時間・生成量の上限を設定する。
- エージェントごとの発言、参照資料、進捗を表示し、全体を停止できる。
- 役割別にモデルを指定できる設計とし、まず一つのモデルを順番に使う構成で成立させる。
- 複数モデルの同時実行はRAM / VRAM容量と実測を踏まえて追加する。
- エージェント同士の一致だけを正しさの証拠にせず、引用した根拠を検証する。

同じモデルを役割別に使う方式も、複数モデルを使う方式も評価する。特に同じ誤りを繰り返す場合、議論が長引く場合、根拠のない合意に達する場合を確認する。

## 共通の画面・実行基盤

- 入力欄に「チャット / Web検索 / 深掘り調査 / ディベート」の作業モードを置き、思考量も選択できるようにする。
- 調査・議論の活動表示、資料一覧、途中結果、最終回答を同じチャット内で扱う。
- 実行中の全体予算を共有し、検索や生成が無制限に続かないようにする。
- Webページは資料として扱う。ページ内の指示でアプリ操作や非公開データの送信を実行しない。
- 外部ページの取得先は公開HTTP / HTTPSに限定する。アプリ内部のAPIやローカルファイルへアクセスする道具にはしない。
- 実行状態と資料の保存・形式移行・終了時の後始末を設計する。

## 推奨する開発順

1. Markdown・コード・出典表示、メッセージ操作、長い会話、停止・復帰を整える。
2. 自前の検索・本文取得基盤を実装し、実通信と停止・保存を検証する。SearXNGそのものを追加する場合は同梱方式と依存・配布条件を別途相談する。
3. Web検索とページ本文取得、出典管理を実装する。
4. その基盤に深掘り調査を追加する。
5. 共通の資料・予算・停止管理を使ってディベートを追加する。

## リリース前の品質確認

- 日本語、要約、計算、コードに加え、Web検索の出典、深掘り調査の網羅性、ディベートの有効性を評価する。
- 通常、読み込み中、ダウンロード中、検索中、調査中、議論中、停止中、エラー時のUIを確認する。
- IME、高DPI、複数モニター、各社GPU、開発環境のないWindowsで確認する。
- 正式バージョン、コード署名、対応OS、更新、依存のソースとライセンス表示、リリース手順を整える。

テキストファイル添付、資料を参照した回答、画像・音声入力も候補として残す。外部ライブラリが必要な機能は依存構成を具体化してから相談する。
