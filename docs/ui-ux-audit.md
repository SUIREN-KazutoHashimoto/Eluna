# UI / UX監査 — 2026-10-15

日常利用の完成度を上げるうえで、優先するのは「編集内容を失わない」「処理の対象と再試行先が分かる」「生成中も読んだり操作したりできる」ことです。モデル選択・思考量・Discord風の会話行という現在の骨格は維持できます。

**この監査時点の記録は42項目。7項目を修正し、35項目を改善候補として記録しました。** その後の修正・検証・残る制約は[UI / UXの改善記録](ui-ux-polish.md)のU01〜U35へ更新しています。以下は修正前の根拠を保持した監査記録です。改善候補には、再現済みの不具合、コードから確認した制約、設計上の改善案を含みます。35件すべてが実行時の不具合という意味ではありません。

## 調査方法と範囲

- `MainWindow`、共通スタイル、設定、モデル検索・管理・取得キュー、推論キュー、プロジェクト・メモリ・参照資料、調査・議論、画像・文書、スキル関連の画面・イベント・状態管理を確認。
- アプリを実際に起動し、WPFコントロール操作と描画、要素の位置・サイズ、AutomationPeerの名前、配色のコントラストを検査。検証用の架空の会話・モデル・添付を使用。
- 主画面1280×900 / 最小820×600、各管理画面の最小サイズ、明暗テーマ、長い名前、長文入力、複数添付、エラー、分岐、停止・送信、処理メトリクスが重なる状態を確認。
- 生成中の操作は、Markdownへ追記することでストリーム更新時の描画経路を再現。今回のUI監査で実モデルの回答品質やGPU演算を再評価したわけではありません。
- 既存の画面検証を再実行し、プロジェクト・資料・ライセンス・モデル取得・参加者の操作と描画も回帰確認。最終追加監査20枚、既存回帰59枚のPNGを出力。

証拠はリポジトリ内のGit管理対象外 `artifacts/ui-ux-audit/` に保存しています。`before/` は修正前の追加監査、`final/` は最終Releaseビルドの追加監査、`regression/` は既存の画面検証です。PNGはWPFの論理サイズを96 DPIの画像へ描画したもので、実機の150% / 200% DPI試験とは区別します。

判定の表記:

- **再現**: 今回のWPF操作・描画・計測で確認。
- **実装確認**: コードに該当経路・制約があることを確認。物理操作による全条件の再現は未実施。
- **改善案**: 現在の画面から判断した使いやすさの提案。不具合の断定ではない。
- **要計測**: 負荷試験等が必要で、現在の性能問題は断定していない。

P1は誤操作・編集の喪失・基本操作を妨げる問題、P2は日常的な理解・操作・アクセシビリティの問題、P3は効率や仕上げの改善としています。
