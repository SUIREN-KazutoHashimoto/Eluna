# プロトタイプを使う

配布物は`Eluna.exe`の一つです。Windows x64で起動し、.NET、Visual C++ランタイム、Vulkan SDK、Pythonなどの環境構築は不要です。GPUを使う場合は、そのGPUに対応する通常のVulkanドライバーが必要です。GPUが利用できない場合は同梱のCPU版を使います。

## 初回の操作

1. `Eluna.exe`を起動する。
2. 「モデルを探す」を開く。小さいモデルの候補を選ぶか、モデル名で検索する。
3. 配布元、容量、利用条件を確認し、GGUFファイルをダウンロードする。
4. モデルが選択されたら、入力欄にメッセージを書いて送信する。初回の送信時にモデルを読み込む。

手元のGGUFは「手元のGGUFを追加」で取り込めます。モデルの検索・取得にはインターネットが必要です。取得済みモデルによる会話はローカルの推論エンジンで生成します。会話をモデル配布元へ送信しません。

## できること

- ChatGPTを参考にした、会話履歴・チャット本文・入力欄のあるダークUI。
- ストリーミング応答、停止、新しい会話、履歴選択、削除、再起動後の履歴復元。
- 公開GGUFモデルの検索、ファイルと容量の選択、進捗表示、中止、次回のダウンロード再開。
- 配布元コミットを固定した取得と、サイズ・GGUFマジック・SHA-256の検証。
- モデルの切り替え、GPU自動選択、明示的なGPU / CPUの選択、コンテキスト長の設定。
- 入力欄のメニューで「速度優先 / 標準 / じっくり」を選択。対応モデルで思考量を変え、選択を再起動後も復元。
- 思考中の表示、回答後の思考時間、生成停止・出力上限の表示。思考と回答のストリームを分けて扱う。
- Enterで送信、Shift+Enterで改行。IME変換中のEnterでは送信しない処理を設けている。
- 文字の選択とコピー。応答は現在、プレーンテキスト表示。

## 保存と配布の仕組み

会話・設定・モデルは`%LOCALAPPDATA%/Eluna/`に保存します。exeの置き場所への書き込みや管理者権限は必要ありません。初回起動時に同梱したCPU / Vulkanエンジンとライセンスを同じユーザーフォルダーへ展開します。

配布用のネイティブエンジンは一体構成でC/C++ランタイムを静的リンクしています。GPU版のVulkanローダーはGPUドライバーのものを使います。CPU版はVulkanに依存しません。標準.NET / WPFランタイムはself-contained single-fileで同梱します。

エンジンはループバック専用の空きポートで起動し、セッションごとのAPIキーで通信します。Windows Job Objectを使い、アプリが終了するとアプリ自身のエンジンも終了します。開発環境の`LLAMA_*`環境変数を子プロセスへ渡しません。

## 応答モード

入力欄の下部にある「標準 ⌄」を開いて思考量を選択します。モデルはチャット領域の左上で選びます。モード変更は次の回答から適用し、モデルの再読み込みは不要です。生成中は選択を固定します。

| モード | 動作 |
| --- | --- |
| 速度優先 | 思考を無効にして回答 |
| 標準 | 対応モデルで、短めの思考を行う（既定） |
| じっくり | 対応モデルで、思考に使える量を増やす |

これは品質の保証やモデルの能力の変更ではありません。思考を使わないモデルではモードを変えても思考量は変わらず、通常の回答を表示します。思考できるモデルでも、質問によって効果や待ち時間は異なります。モデル自体はモデル選択欄から変更します。

内部では標準に最大512、じっくりに最大2048トークンの思考枠を設定し、llama.cppの`enable_thinking`、`reasoning_effort`、`reasoning_budget_tokens`へ渡します。会話の入力トークン数をローカルで数え、回答用の余地を残して思考枠と出力上限を縮めます。回答する余地がほとんどない場合は、新しい会話かコンテキスト長の変更を案内します。

生成中は「考えています…」、回答後は思考ストリームの受信にかかった時間を表示します。保存するのは回答、モード、所要時間、停止などの状態です。思考本文は履歴・次のモデル入力に含めません。従来の履歴はそのまま読み込めます。

## 開発者向け

```powershell
./scripts/Setup-VulkanSdk.ps1
./scripts/Publish.ps1
```

出力は`artifacts/release/Eluna.exe`です。ネイティブの配布用ビルドが完成していれば`-SkipNativeBuild`で省略できます。ビルド時のみ、NuGetから標準.NETランタイムとSDKの単体配布用ツールを取得します。取得元のマッピングをこの範囲に限定し、明示的なC#外部PackageReferenceは引き続き拒否します。

起動中のexeを残して別の配布物を作る場合は、`./scripts/Publish.ps1 -SkipNativeBuild -OutputDirectory artifacts/release-ui-fix`のように出力先を指定できます。

```powershell
./scripts/Verify.ps1
dotnet run --project tests/Eluna.Checks -c Release -- --integration artifacts/prototype-checks
```

Verifyは外部モデルを取得しないチェックを実行します。integrationは実際に公開モデルを取得してSHA-256を検証し、GPU / CPU生成、停止、切り替え、後始末を確認します。テストフレームワークの外部パッケージは使用しません。

## 確認した範囲と制限

2026-10-14にRX 9070 XTとQwen3.5-0.8B Q4_K_Mで、公開API検索、ダウンロード、ハッシュ検証、GPU応答、停止、CPU切り替えを確認しました。履歴と設定の復元、破損履歴の原本保管、分割受信、中断ダウンロードの再開は自動チェックで確認しています。

同じ実モデルで3段階の応答モード、思考と回答の分離、思考中の停止を確認しました。モード選択・設定保存と、通常サイズ / 小さいウィンドウ / メニュー / 思考中のWPF描画も確認しています。回答の正確さが改善する割合はまだ評価していません。

exeだけを別のフォルダーへコピーし、インストール済み.NETの探索を無効にした状態で、同梱エンジンの展開、GPU / CPU応答、GUI描画を確認しました。WPFのネイティブDLLもexeの展開先から読み込まれています。

その後の開発版では分割GGUF、Markdown、会話の編集・分岐・検索、モデル管理、バックアップ、Web検索、深掘り調査、ディベートを追加しました。[現在の使い方](using-eluna.md)と[実装・検証の台帳](implementation-status.md)を参照してください。ログインが必要なモデル、画像・音声入力、任意のツール実行は対象外です。モデルとメモリ容量によって読み込みや応答の速さは変わります。

クリーンな別PCでの確認、実際の日本語IME操作、スクリーンリーダー、200% DPI、他社GPU、コード署名はまだリリース前の確認事項です。
