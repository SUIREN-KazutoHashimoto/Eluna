# スキル

管理画面の「変更差分」で、保存した版と編集中の手順・資料・コード・適用／実行設定を比較できる。追加・削除・パス変更を含み、全文の切り替えも可能。大きなファイルとバイナリは容量・SHA-256で比較する。操作と検証は[残機能の実装記録](remaining-features.md)を参照。

## 使う

入力欄の「スキル」から、自動・指定のみ・オフを会話ごとに選ぶ。「管理・取り込み」または設定のスキルタブから管理画面を開ける。

チャット領域が狭い場合は、入力欄の「⋯」を開いて「スキル」を選ぶ。同じメニューから検索・調査・ディベート参加者の設定も開ける。

管理画面ではSKILL.mdを含むフォルダー、ZIP、`.skill`を取り込み、内容を確認して保存する。取り込んだだけでは登録しない。名前・用途の説明・手順をGUIから新規作成・編集でき、参考資料や補助コードも追加・編集できる。保存した版はZIPまたは`.skill`へ書き出せる。配布元のライセンスと動作条件は「適用・実行」で確認する。

「標準スキルを追加」で、Eluna用に作成した日本語推敲、議事録、数値集計の3件を現在の範囲に追加する。Anthropicの既製スキルは同梱していない。標準スキルはApache-2.0で、書き出すパッケージにもLICENSEを含める。

- **自動**: 名前・説明の強い一致を補助に使い、ローカルモデルでも適用候補を判断する。意味検索や大規模な精度評価を行った分類器ではない。モデル、説明、依頼の書き方により選択を見落とす場合がある。
- **指定のみ**: 入力欄で選んだスキル、または`/skill-name`で指定したスキルの手順を読み込む。最大3件。オフでは会話で選んだスキルを使用せず、明示コマンドにはオフを解除する案内を出す。
- **使用記録**: 回答の「使用スキル」から、使用版・選択理由・手順・実際に読んだ抜粋・補助コードの入力と実行状況・作成ファイルの保存先を確認する。文書生成にも指定と自動適用を使い、生成画面の「使用スキル」で確認できる。文書生成画面の記録はその画面のセッション内に保持する。

スキルごとに主な資料または最後の補助コード出力の抜粋を、回答のナレッジ参照にも最大1件ずつ加える。プロジェクト等の参照と合わせて8件までで、スキルの参照分は従来の優先度が低い候補と入れ替える。出典番号と実際の抜粋を対応させ、全体の手順・資料・実行結果は使用スキル画面で別に確認できる。

## 形式と互換性

名前・説明・本文と、必要な補助ファイルをパッケージにする基本構造は[Agent Skills仕様](https://agentskills.io/specification)を基準に実装した。動作の比較には[Claudeの公式概要](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)を参照した。

```text
my-skill/
  SKILL.md
  references/
    guide.md
  scripts/
    helper.ps1
  assets/
    template.csv
```

```markdown
---
name: my-skill
description: 何をするスキルか、どの依頼で使うかを具体的に書く。
license: Apache-2.0
compatibility: Windows; Eluna; standard PowerShell only
---

# 手順

1. 依頼された条件を確認する。
2. 必要な場合はreferences/guide.mdを読む。
3. 結果を根拠とともに示す。
```

対応範囲は次の通り。

| 項目 | Eluna |
| --- | --- |
| SKILL.md | UTF-8 / UTF-8 BOM。名前は64文字以内の英小文字・数字・単一ハイフン。説明は1〜1024文字 |
| YAML | 通常の文字列、単一・二重引用符、`>` / `|`とchomping指定。ライセンス・互換性と入れ子の任意メタデータは保持。汎用YAML実装ではなく、名前等でのタグ・エイリアス・配列・オブジェクトは受け付けない |
| ZIP | 1スキル。直下のSKILL.md、または名前が一致する単一スキルフォルダー。複数スキルのリポジトリZIPは個別に取り込む |
| 同梱資料 | テキストは必要なファイルを読み込む。バイナリのテンプレート等は保存・書き出し・補助コードへの受け渡しに対応 |
| 補助コード | Windows標準PowerShell 5.1。Python・Bashランタイム、ClaudeのVM、外部パッケージの同梱・自動導入はしない |
| `allowed-tools` | 原文を保持するが権限の許可として扱わない。Eluna側の実行設定を使う |
| Claude専用機能 | AnthropicのAPI、クラウド環境、既製の文書スキルとその依存環境を再現するものではない |

名前と説明を編集しても、元の任意メタデータを保持する。対応外のコードを含むスキルもパッケージとして保存できるが、その実行が必要な手順の完全動作は保証しない。

## 段階的な読み込み

最初の選択では名前・説明を使い、選択されたスキルの本文を読み込む。その後、モデルが必要な同梱テキストや補助コードを選ぶ。手順中で「必ず」「must」「required」「always」と同じ行に指定した`references/`のファイルはアプリ側でも先に読み込む。条件付きの参照はモデルの判断に任せる。

動作に必要な入力枠が不足する場合は、モデルの記憶長を増やすかスキルを短くする。現在の主な上限は次の通り。

- 登録は200件、1パッケージ256ファイル・合計32 MB、各ファイル16 MB、SKILL.mdは128 KB。
- 1回の適用は3スキル。モデルの選択候補は説明の一致で並べた最大12件。
- 補助処理の計画は最大4回、各回2操作。テキスト参照は6件、補助コードは2回。
- 参考テキストの読み込み対象は128 KB以内、モデルへ渡す抜粋は各8,000文字まで。全ファイルの全文を無制限に読む構成ではない。実行候補の一覧は各スキル64ファイルまでで、手順に明記されたパスも登録内で検証する。

資料・検索結果内の命令をツール呼び出しとして直接実行しない。モデルが選んだ操作も、対象スキルの実在するファイルに限定して検証する。外部への検索は従来のチャット・調査の制御下で行う。スキルの手順や生成結果がモデルの能力を超える場合の品質は、使用記録と元資料で確認する。

## プロジェクトと推論予約

プロジェクトで作ったスキルはそのプロジェクトに所属する。通常チャットは共通スキルを使う。プロジェクトでは共通スキルを初期状態で除外し、管理画面の「このプロジェクトで共通スキルも使う」を明示的に有効にした場合だけ候補に加える。資料・メモリの参照範囲は変えない。同名の場合はプロジェクトのスキルを優先する。

予約には利用可能な名前・説明・ID・版と明示指定を保存する。自動選択は実行時の質問と予約時の候補で判断し、本文や同梱ファイルは予約した版から読む。更新・登録解除しても既存の予約の版を書き換えない。後続メッセージ、別のチャット、別プロジェクトの選択状態を使わない。コード実行の許可は現在の登録・有効状態も確認し、無効化・登録解除・実行禁止へ変更したスキルを実行しない。

停止後のチャットを再実行する場合、補助処理も再度計画する。確認が必要なコードは再び確認する。既存の調査チェックポイントを再開する場合は、すでに読み込んだ手順・資料・実行結果を引き継ぎ、同じ補助コードを自動で繰り返さない。

## PowerShellの補助コード

アプリが直接起動する補助コードは`scripts/*.ps1`で、次のインターフェースを使う。

```powershell
param([string]$InputJson, [string]$OutputDirectory)
$inputData = Get-Content -LiteralPath $InputJson -Raw -Encoding UTF8 | ConvertFrom-Json
# 作成するファイルはOutputDirectoryへ保存する。
# 標準出力にモデルへ返す結果を出力する。
```

入力JSONはファイルのパスとして渡し、コマンド文字列へ連結しない。スキル一式を専用の作業フォルダーへコピーする。PowerShellコードと入力は日本語を扱えるUTF-8 BOMで用意し、標準出力・標準エラーを読み取る。上限は60秒、各出力16,000文字、作成ファイルは20件・合計32 MB・各16 MB。キャンセルとアプリ終了ではWindows Job Objectを通じて補助プロセスを終了する。

コードは**Windowsのユーザー権限**で動き、OSによるファイル・ネットワーク隔離は実装していない。作業フォルダーは出力先の整理とスキル参照の制限であり、スクリプト自身のアクセスを隔離するものではない。

初期設定は実行ごとの確認。スキル名、コード全文、入力JSON、出力先を別ウィンドウで確認して許可または拒否でき、他のチャットの閲覧を妨げない。確認済みの版について自動実行を許可する設定もある。「検索しない」ではこの設定にかかわらずコード実行を毎回確認する。これはコードが任意の通信を行えるためで、アプリのWeb検索停止とは別の許可となる。

## 保存・取り込み・削除

登録と会話設定は`state-skills.json`（形式3）、不変の版ファイルは`Skills/<ID>/<SHA-256>/`、生成ファイルは`Generated/Skills/`へ保存する。登録または会話のスキル設定を初めて保存すると新形式へ移り、旧版用の`state.json`と`state-knowledge.json`は保持する。旧版との同時編集・自動合流は行わない。

ファイル名、サイズ、内容のSHA-256を保存し、読み込み時に変更を検出する。ZIPの範囲外パス・重複名・Windowsで不正な名前・シンボリックリンク／ジャンクションを拒否する。

登録解除とプロジェクト削除では、通常の選択肢から外す。予約・使用記録のため版ファイルは保持し、自動消去・完全消去はしない。キャンセルや失敗で生成した作業フォルダー、保存に失敗した一時フォルダーが残る場合もある。

履歴のバックアップ・JSON書き出しには登録情報・指定・使用記録・予約を含めるが、版の実ファイルと生成ファイルは別管理。同じ保存先のバックアップ復元では残っている版を利用する。別PCへの移行では、スキルをZIP等で別途書き出して取り込む。履歴の取り込みでスキルの登録やコード実行許可を自動移入せず、プロジェクトの共通スキル利用も初期状態へ戻す。過去の使用記録には指示・読んだ抜粋・補助コード出力が残り得る。
