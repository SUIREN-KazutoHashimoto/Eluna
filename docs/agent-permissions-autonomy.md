# アカウントの権限・性格・自動編成

ElunaのローカルAIアカウントに対する設定。利用者本人は管理者で、全サーバー・チャンネル・履歴・バックアップを開ける。複数の人間のログイン認証や、保存ファイルの暗号化・OSアクセス制限を提供する機能ではない。

## チャンネルのアクセス権

チャンネル名の「⋯」→「アクセス権」、または設定 → チャンネル →「チャンネルのアクセス権」を開く。対象は開いたときのチャンネルに固定する。

| 権限 | 用途 |
| --- | --- |
| 閲覧 | 過去会話・添付の参照。同じサーバーの検索、持ち越し履歴・保存メモリの作成元にも適用 |
| 発言 | 応答・議論・音声・Computer Use・画像／文書生成を実行。現在のメンバーであることも必要 |
| 招待 | 自動編成で、登録したつながりのあるAIを作業先へ招待 |
| 作業場所の作成 | 自動編成によるサーバー・チャンネルの作成 |

現在のメンバーは初期状態で閲覧・発言が可能。招待・作成は初期状態では不可。メンバー外は初期状態で閲覧不可。「閲覧のみ」を明示したメンバー外のAIは、参照範囲の設定も許可している場合にその場所を参照できるが発言できない。発言を許可するだけではメンバーへ追加されない。

「アクセス不可」「閲覧のみ」「閲覧・発言」「作業を任せる」でまとめて選べる。スレッドの閲覧には親チャンネルの閲覧も必要。同じサーバーの資料はサーバー単位の共有で、チャンネルACLは資料個別のACLではない。資料を分離する場合は別サーバーに置く。

権限を変更すると関連する推論・予約・Computer Use・生成を停止する。音声の応答アカウントが発言できなくなった場合は通話を終了する。再開時にも参照設定を検証する。既に投稿・引用・要約された内容は過去の履歴として残り、権限変更で回収・削除はしない。

通常の応答には話者本人が閲覧できる参照のみ渡す。議論の共通資料には、発言可能な参加者全員が閲覧できる会話のみ含める。個人の持ち越しメモリは個々の発言時に渡す。

## 性格・ロールプレイ

メンバーや発言者のアイコンからプロフィールを開き、「性格」で標準・相棒・分析家・批評家・先生・クリエイター・キャラクターを選ぶ。役柄・世界観・口調を任意で補足できる。既存の基本指示・専門分野と合わせ、通常応答・議論・資料生成に使う。

設定 → アカウントのプロフィールからも編集できる。過去の発言者名・使用モデル・保存メモリは保持する。通常の予約は予約時の指示を保持する。自由形ディベートは次の発言からプロフィールの変更を使う。役柄を設定しても、その能力や会話外の経験を実際に獲得するものではない。

## AIによる自動編成

1. 進行役のプロフィール →「つながり・自動編成」を開く。
2. 招待候補のアカウントを選ぶ。つながりは片方向。候補側の「自動招待を受ける」も必要。
3. 自動編成・チャンネル作成・必要ならサーバー作成と招待をオンにする。
4. 依頼元のアクセス権で、進行役に「作業を任せる」を設定する。
5. 普通に依頼する。例えば「新しいサーバーと作業チャンネルを作って、設計担当と検証担当で案を比較し、ここへ報告して」。

ローカルモデルが必要性・担当・場所を構造化した計画として出す。簡単な依頼では通常応答へ進む。許可外の相手・作成数・不完全な計画を検出すると、作成前に中止して処理リストに理由を示す。自動編成は初期オフで、既存アカウントを勝手に有効化しない。

招待先に共有するのは担当に必要な依頼文と同じ作業チャンネルで先に完成した担当結果。依頼元の履歴・添付・資料をコピーしない。新規サーバーは限定メモリ・履歴相互参照なし・持ち越しメモリ受入なしで作る。既存サーバー内に作成した場合、そのサーバーの共通資料・指示・メモリは通常の範囲で利用する。招待した相手に依頼元の閲覧権を与えることもない。

最大1サーバー・3チャンネル・6担当。全体300秒・出力予算8,192トークン、個別担当の通常回答は最大512トークン。既存の推論枠1件を使い、担当を順に実行する。作業先を予約中は同チャンネルの通常推論を待たせ、設定した並列数を超えるエンジンを増やさない。担当からさらに自動編成は行わない。検索指定・検索禁止は各担当にも反映する。

担当の発言はアカウント・モデル付きで各作業チャンネルに保存し、進行役が結果を依頼元に報告する。「チームで作業中／完了」カードから担当の場所と途中結果を開ける。処理リストまたはカードで停止でき、中断した作業はカードから再開できる。完了済みの担当と作成済みの場所は再利用する。権限変更・作業先削除・移動・モデル不足では再開を拒否し、無断で別の場所へ差し替えない。アプリ再起動時に勝手に続行しない。

現時点では通常チャット・必ず検索・検索なしのテキスト依頼が対象。添付がある会話、4,000文字を超える依頼、ディベート・深掘り調査・Computer Useモードの依頼は既存の処理へ進む。人格・担当分け・報告の品質は使用モデルに依存する。作業場所の作成はローカルデータの変更であり、外部サービスや他の人への招待送信ではない。

## 入力中表示

実行中の話者だけを入力欄の下に「〇〇 が入力中…」と3点の動きで示す。予約だけの状態・議論の手動待ち・計画の確認待ちでは表示しない。チーム作業では各担当が実行しているチャンネルに表示し、報告中は依頼元に表示する。完了・停止・移動で更新する。Windowsでアニメーションを無効にしている場合は点を静止させる。

## 保存と互換性

既存のワークスペース形式へ省略可能な項目として追加。全体ZIPでは権限・性格・つながり・チーム進捗を保持する。履歴を別コピーとして取り込む場合はアカウント・チャンネル・発言・担当のIDを付け替え、自動編成をオフにする。モデル本体・音声・外部実行権限を新たに取得する機能ではない。新しい外部依存は追加していない。

## 確認方法

`scripts/Verify.ps1`でACL継承・同サーバー参照の共通部分・閲覧のみ・メモリ作成元の拒否・性格の指示合成・招待候補の制限・計画の検証・保存／取り込み／ZIPを確認する。

専用の保存先を指定し、`Eluna.exe --verify-agents <出力先> --data-dir <専用データ>`でWPF操作・権限拒否時の下書き・Computer Use／文書経由の拒否・予約取消・明暗テーマ／最小サイズ／文字130%を確認できる。`--model-meta <model.json>`を加えると、実モデルによるサーバー・チャンネル作成、招待、担当の回答、報告、入力中表示と解除、依頼元との分離と保存を検証する。
