プロフィール編集、プロジェクト＝サーバー、ボイスチャンネル、ウィンドウ共有とComputer Useの入口、および重なり対策を追加しました。[現行の仕様・操作と検証範囲](voice-channels.md)を参照してください。

## 使い方

1. 左端でサーバーまたはDMを選ぶ。サーバーは既存のプロジェクトと同じ作業領域で、指示・資料・保存メモリを共有する。
2. 左上の「エージェント」でアカウントを作る。名前、文字・絵文字のアイコン、基本指示、専門分野、モデルを設定する。モデルを変えてもIDは変わらず、無効化しても履歴は残る。
3. 「＋ チャンネル・DM」でチャンネル、DM、グループDMを作る。参加者はドラッグ＆ドロップ、追加・退出、上下移動で編集できる。最大6名。
4. 中央上部の宛先を選んで送信する。`@名前 質問`、空白を含む名前の`@{名前} 質問`、`@全員`にも対応。同名の参加者にはメニューで指名する。全員宛ては各エージェントの返答としてキューへ入る。
5. 発言の返信操作で返信先を指定する。引用から元発言へ移動でき、発言メニューからスレッドを作れる。スレッドに渡す親の文脈は元発言までで、その後の発言・まとめは渡さない。従来の分岐も保持する。

場所ごとに下書き・作業モード・思考量を保持する。モデル選択は左上、思考量は入力欄。名前・モデル・時刻は発言時の記録を表示し、不明な旧時刻・モデルは補わない。通常の返答、議論の各発言、司会のまとめ、生成物を中央へ表示する。

## 履歴と記憶

「エージェント → 全会話履歴」では参加した場所を検索し、元の発言を開ける。履歴の保持と推論への持ち込み許可は別に管理する。履歴をバックグラウンドで走査し、結果を200件ずつ表示する。

既定では他の場所の履歴を持ち越さない。「チャンネルの設定」に参照範囲を表示する。

| 対象 | 条件 |
| --- | --- |
| 現在の会話 | 現在の分岐。モデルの上限に合わせて既存の文脈圧縮を適用。 |
| 同じサーバーの別チャンネル | サーバー管理の別会話参照と、利用先チャンネルの両方で許可。 |
| エージェントの過去会話 | 作成元で履歴の持ち越しを許可し、そのエージェントが参加していること。利用先チャンネルが受け入れ、サーバー内ならサーバーでも受け入れを許可。 |
| 場所限定の保存メモリ | 作成元の会話と、その会話から作ったスレッド。 |
| サーバー限定の保存メモリ | 同じサーバー内の、そのエージェントの参加先。 |
| 持ち越し用の保存メモリ | 作成元、または受け入れを許可した参加先。メモリを明示的に共有する操作なので、履歴全体の共有は不要。 |

保存メモリは「エージェント → 保存メモリ」で作成・編集・無効化・削除する。1件4,000文字まで。全履歴をプロンプトへ入れず、依頼に関係する抜粋を選ぶ。既存資料と合わせて最大8件・文字予算内、エージェント由来は最大4件。回答・議論の発言から参照抜粋を確認でき、作成元会話・エージェント・メモリのIDも保持する。

許可やメモリの変更時は関連する推論・予約・生成・Computer Useを停止する。無関係な場所の処理は継続する。再開時も保存した参照許可を照合する。取り消しても過去の回答に引用済みの本文は残る。

別サーバーへの会話移動時は持ち越し許可を解除し、以前の所属のメモリを無効化する。スレッドは親と一緒に移動する。削除時は子スレッドと作成元メモリも対象。アカウントの無効化で既存発言は削除しない。

## 議論

入力欄を「ディベート」にし、「⋯」の調査・参加者設定でラウンド制／自由形式、上限、検索を設定する。1名だけの既存会話から開始すると、設定済みの役割からその場所の参加アカウントを作る。

ラウンド制は参加者の順番とラウンド数に従う。自由形式は司会が質問・反論・補足・保留・次の話者・追加検索を選ぶ。司会は開始時に選択したモデルが兼任する。構造化出力を検証し、未知の参加者や他の議論の返信IDを拒否する。無効な進行案が3回続いたら手動へ切り替え、3回連続での発言独占と同じ発言の反復も抑える。

- 「自動進行」オン／オフ。「次の発言」で一人ずつ進め、宛先で発言者を指名する。
- 入力欄から利用者も発言できる。通常の追加指示は区切りで反映。「入力内容で割り込む」は生成を停止し、最新の指示で再開する。中断した発言はその旨を表示して残す。
- 「参加者」で追加・退出・順序変更。プロフィール更新は次の発言へ反映し、既存発言の表示は保持する。
- 「一時停止」「再開」「ここまで整理」「まとめて終了」。未完了の発言と残り予算を保存し、確定済み発言を再生成しない。

自由形式の既定値は最大12発言、5分、全工程8,000 token。既存の上限設定を引き継ぎ、変更可能。司会・検索語・途中整理も同じ予算を使い、最終整理の枠を確保する。計画確認と手動の発言待ちは実行時間に含めない。一議論内は一人ずつ推論し、別の場所は既存の同時実行設定に従う。

検索は「自動」「必ず」「使わない」。開始時に検索不要でも、必要になれば追加検索する。明示的な検索依頼は残り予算内で試みる。検索しない指定を守り、重複を除去し、失敗も活動に残す。資料未取得なら外部資料で確認していないと表示する。発言の一致を事実の証明と扱わない。

## 既存機能・保存・移行

深掘り調査、添付、スキル、Computer Useの既存経路を維持する。アカウント作成で補助コード・Windows操作の許可は与えない。画像・文書の依頼と生成物は予約時のチャンネル・分岐・エージェントへ関連付け、別の場所を見ていても作成元へ結果を表示する。「開く」で結果を再表示できる。

文書下書きは会話ごとのファイルへ保存する。旧プロジェクト単位の下書きは削除せず「下書きを開く…」で読み込める。履歴JSONは生成物のリンクを含むが、ファイル本体の持ち運びには全体ZIPを使う。

新形式はschema 4の`state-workspace.json`。旧`state.json`、`state-knowledge.json`、`state-skills.json`を残したまま移行する。旧プロジェクトはサーバー、配下の会話はチャンネル、所属のない旧会話は「移行した会話」として個別に残す。分岐・添付・資料・メモリ・旧議論も保持する。

新形式が壊れたら`state.broken-*.json`へ退避し、残っている旧形式から回復を試みる。旧形式へ戻る場合は移行後の最新会話を含まないため、回復通知と退避ファイルを確認する。通常は定期的に全体ZIPを保存する。

全体ZIPはアカウント、所属、返信、スレッド、メモリ、議論の進行状態、生成物本体を復元し、絶対パスを復元先へ合わせる。再起動後の予約は自動実行しない。履歴JSONの取り込みはアカウント・サーバー・会話・発言・メモリのIDを再割り当てし、同名の既存アカウントに混ぜない。
