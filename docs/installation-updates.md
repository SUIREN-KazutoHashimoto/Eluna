# インストール・更新トレイン

配布物は`Eluna.exe`（単体起動）と`Eluna-Setup.exe`（インストール）です。同じ自己完結型の本体を使い、.NET・Visual C++ランタイム・Vulkan SDKの利用者による導入は不要です。画像・会話モデルは別途取得します。セットアップは自作WPFで、外部のインストーラーパッケージを使いません。

## 導入と削除

`Eluna-Setup.exe`を起動してインストールします。保存先は`%LOCALAPPDATA%\Programs\Eluna`。利用者単位のアプリ登録と、任意のスタートメニュー・デスクトップのショートカットを用意します。管理者権限、ドライバーやOS全体の設定変更は要求しません。開発ビルドからのインストールは拒否します。

会話・モデル・生成物の標準保存先は従来どおり`%LOCALAPPDATA%\Eluna`です。Windowsのアプリ一覧または`Eluna.exe --uninstall`で本体を削除しても、そのデータは残します。インストール記録のIDを確認し、アプリ所有の既知のファイル・一致するショートカット・自身のアプリ登録だけを削除します。

## 更新

設定の「外観・操作」→「バージョン・更新内容を確認」で、次を選べます。

- 正式版：`main`から公開された正式リリース。
- 開発版：`develop`向けの開発ソースから公開された`-develop.N.N`、`-beta` / `-beta.N`、`-rc` / `-rc.N`のプレリリース。下書きは対象にしません。
- 自動更新の有効・無効。標準は正式版・有効。

自動適用はインストール版で利用できます。単体exe版では確認・取得とインストールへの案内を表示します。トレインの変更で古い版へ自動的に戻すことはありません。

起動後と約3時間ごとに公式GitHubを確認します。取得は中止でき、完成した取得は再起動後も再検証して再開します。推論・取得・生成・予約や再開待ち・VCがある間は適用しません。自動で再起動するのは、メイン画面が非アクティブで、子画面も入力中の文章もない場合です。明示的な「再起動して適用」も用意します。終了時には通常どおり下書き・履歴を保存します。

取得前に公式リポジトリ・タグのURL、容量、GitHubのSHA-256を確認し、取得後にマニフェストの版・トレイン・容量・ハッシュ・データ形式を照合します。ハッシュがない旧リリースや、現行データ形式5に対応しない版は自動適用できません。これは公式配布元と整合性の検査であり、Authenticode署名の用意は今回の実装に含みません。

適用用の別プロセスが旧プロセスの終了を待ちます。既知の状態ファイルを退避し、`File.Replace`で本体を置き換え、旧exeを`Eluna.previous.exe`へ保持します。新しいWPF画面の準備完了を確認できなければ旧exeと退避した状態へ戻します。同じ失敗版を自動で繰り返さず、更新画面から再試行できます。背景での更新後は最小化して起動します。

## 保存形式と互換性

現行の会話・アカウントは形式5の`state-social.json`へ保存します。旧版の`state-workspace.json`以下の形式1〜4は上書きせずに読み込み・移行します。全体バックアップも新形式を含みます。旧版を手動で実行した場合は、旧形式に残っている時点までの会話しか読み取れません。新形式で増えた会話を旧版へ同期する機能はありません。

## GitHubの公開経路

`.github/workflows/release.yml`は`develop`へのpushでプレリリース、`main`へのpushで正式版を作る構成です。C#の検証、固定エンジンのCPU/Vulkanビルド、配布物検査を通してから下書きリリースへアップロードし、GitHub上のハッシュ・容量が一致した場合だけ公開します。開発版をLatestにはしません。

正式版の基底バージョンは`Directory.Build.props`で管理します。公開済みのタグ・ファイルを上書きせず、次の正式リリース前に基底バージョンを上げます。開発版はその基底版と実行番号・試行番号を使います。`main`への統合は従来どおり`develop`からのリリースPRです。

初回の[0.1.0beta](https://github.com/SUIREN-KazutoHashimoto/Eluna/releases/tag/v0.1.0-beta)は、develop向けPRの最新コミットを固定タグ`v0.1.0-beta`で配布する手動プレリリースです。表示名は`0.1.0beta`、exe・マニフェスト内は標準的なバージョン表記`0.1.0-beta`を使用します。正式版のLatestにはしません。PRの統合と`main`からの正式公開は別の操作です。

上記の自動公開ワークフロー、ホスト側の権限・保護ルール設定は実GitHubでの動作確認が済んでいません。ワークフロー自体に変更を含む開発リリースでは、GitHubのトークン／既定ブランチの制限により公開を拒否される場合があります。

## 確認した範囲

`artifacts/update-portable-1/result.json`で、実際の単体exeを隔離先へ導入し、旧プロセスの終了待ち、本体置換、新しいWPF画面による起動確認、旧exeとモデルの保持を確認しました。検証では実利用環境のレジストリ・ショートカットを変更していません。失敗時の状態復旧、破損・異なるタグ・互換性のない版の拒否、正式版／開発版の分離はコンソール検証でも確認しています。

別PC、物理IME、実DPI変更、電源断、Windowsの実アプリ一覧からの削除、実GitHub配信による更新は未確認です。ローカル検証結果とGitHub上の公開成功は区別します。
