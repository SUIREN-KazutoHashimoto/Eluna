# Computer Use

選択したWindowsアプリを、ローカルモデルが画面とUI要素から判断して操作する開発版機能です。アプリの種類をメモ帳やブラウザーへ限定していません。すべてのWindowsアプリで動作する保証はなく、アプリ側のUI公開・画面取得・Windowsの入力制約に左右されます。

## 使い方

1. サイドバーの「Computer Use」、または入力欄の「＋」から開きます。
2. 操作するアプリを開き、「一覧を更新」します。クリックまたはSpaceで1〜8個の対象ウィンドウを選択します。「画面を確認」で取得内容を確認できます。
3. 操作を考えるモデルを選び、依頼を入力します。画像対応GGUFと対応するprojectorを画像・文書画面で設定すると、画面画像とUI要素を併用します。projectorがなければUI要素だけを使い、要素を指定した操作に限定します。ドラッグには画像入力が必要です。
4. 「操作を開始」で、画面取得→次の操作の提案→確認→実行→画面の再取得を繰り返します。初期設定では待機以外の各操作を確認します。文字入力の提案は確認欄で修正してから実行できます。
5. 「実行せず終了」で次の操作を実行せず停止します。「停止」または **Ctrl+Alt+Esc** では確認待ち・モデル生成・画面取得も中断します。実行済みの入力や保存は取り消されません。

「移動・スクロール・待機だけ自動」を有効にすると、許可した対象の切り替え、スクロール、Tab・矢印・PageUp/Down・Home/End・Esc等の移動キーは確認を省略します。クリック・文字入力・EnterやCtrlを伴うキーは毎回確認します。この設定は画面を開き直すとオフへ戻ります。

実行中はマウスとキーボードを共有します。操作を続ける必要があれば先に停止してください。主画面の「処理リスト」から状態の確認、操作画面への復帰、停止ができます。Computer Use画面を閉じると中断します。アプリ終了時も中断し、モデルと補助プロセスを終了します。再起動後の自動再開や操作の再送は行いません。

## 操作と範囲

対応する提案は、クリック、ダブルクリック、右クリック、Unicode文字入力、入力欄の値の置き換え、単一のキー組み合わせ、スクロール、ドラッグ、許可対象の切り替え、待機、利用者への引き継ぎ、完了報告です。クリックは取得したUI要素を優先し、UI AutomationのInvoke/Select/Toggle/Expand等を使います。画像モデルではスクリーンショット内の座標も使えます。

許可対象は開始時に固定します。別のアプリを追加する場合は停止して選び直します。対象のプロセスID・開始時刻・ウィンドウ、所有ポップアップ、位置、UI要素、画像の差分を実行前に再確認します。変化があればその案を実行せず考え直し、3回連続で変化した場合は停止します。動的な時計やアニメーションが多いアプリでは、この確認で停止しやすくなります。キー入力前には対象のフォーカスも確認します。

モデルには、この画面へ入力した依頼、許可対象の名前、対象画面・UI要素、直近の操作結果を渡します。会話本文・プロジェクト資料・メモリ・スキルは自動で渡しません。画面に書かれた指示を依頼と区別するプロンプトを使いますが、モデルの誤読や画面内の悪意ある指示への耐性を保証するものではありません。実行する操作と入力文字は確認画面で確認してください。

モデルへの指示では、プログラムの起動・端末・コマンド実行・セキュリティ設定・認証・CAPTCHA・購入／支払いは利用者へ引き継ぎます。Windowsキー、Alt+Tab、Ctrl+V/X等は実行プロトコルで拒否します。UI Automationがパスワードと報告した欄は本文と画像をマスクし、操作対象から除きます。パスワード属性を公開しない独自コントロールや、画面にそのまま表示された秘密情報は検出できません。OSによる隔離や操作のロールバックはありません。

## 上限と保存

- 依頼は8,000文字、対象は1〜8ウィンドウ、操作上限は10 / 20 / 40 / 100回から選択します。実行時間は確認待ちを含め20分までです。
- UI要素は最大256件、探索は最大640要素・深さ16、スクリーンショットは長辺1,280pxまでに縮小します。画像取得元は最大8,192px／1,600万画素です。
- 画面取得と入力は、同じexeから起動する使い捨て補助プロセスで処理します。1要求12秒で打ち切り、中断時は補助プロセスを終了します。デスクトップ操作は同じログインセッションで同時に1件だけです。
- 推論には独立したllama.cppプロセスを使います。通常チャットの同時実行枠には含めません。チャットや画像生成と同時に使う場合は追加のRAM／VRAMが必要です。
- 画面画像・依頼・履歴を通常の状態ファイルへ自動保存しません。履歴は次の実行開始や画面を閉じる操作で失われます。「履歴を書き出す」を選んだ場合だけJSONへ保存し、そのJSONには依頼・入力文字・アプリ名・理由と結果を含みます。スクリーンショットは含みません。

## 制限

対象アプリは表示した状態で使用します。最小化中、ロック画面、UAC等の保護画面、異なる権限のアプリ、UI要素や画像を取得できないアプリでは停止する場合があります。通常のウィンドウ取得に失敗した場合は、前面の対象領域だけを取得し、重なった別ウィンドウの領域を隠します。保護された画像やGPU描画の取りこぼしが起きる場合があります。

Windowsが前面化を許可しない場合は「対象アプリを前面にできませんでした」と表示して停止します。対象をクリックし、状態を確認して再実行してください。Windowsの制限を解除したり、管理者権限へ昇格する処理はありません。これらは[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)と[SendInputの権限制約](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)に従います。

完了表示はモデルによる観察結果の報告です。保存先や入力結果は対象アプリでも確認してください。実モデル確認で、指定した半角記号を全角へ変える提案や、不完全なJSONを出す例を確認しました。入力の修正機能、理由の長さの制限、不正な提案を実行しない処理を用意していますが、モデルによるアプリ理解や作業の成功率には継続した評価が必要です。

## 検証

`./scripts/Verify.ps1`に、操作形式、不正なキー、許可対象、画面変更、確認の拒否・文字修正、キャンセル、操作回数、同時操作の排他を含めています。UI Automationは[Microsoftのスレッド指針](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)に沿ってUIスレッドから分離しています。

実機確認には、利用者データを使わない専用画面を用います。次のコマンドはその画面と検証用のElunaを起動します。専用画面を前面にすると、日本語入力・保存・実モデル操作を開始します。検証中の承認は専用画面の作業に一致する提案だけを許可します。

```powershell
Eluna.exe --verify-computer <検証結果フォルダー> --data-dir <空の専用データフォルダー> --model-meta <画像対応モデルのmodel.json>
```

実機ではQwen3.5-4B Q4_K_M＋projectorとVulkanを使い、日本語Unicode入力、UI要素への値設定、座標クリック、モデルが入力→保存→保存済み表示を確認する処理、パスワード本文・画像のマスク、古い画面の拒否、Ctrl+Alt+Esc、応答停止した対象への取得の中断を確認しました。明暗テーマ・最小900×640・文字130%の描画も確認しています。

2026-10-15の最終検証結果は`artifacts/computer-use-verify.log`、配布ログは`artifacts/computer-use-publish.log`です。`artifacts/release-computer-use/Eluna.exe`だけを`artifacts/computer-use-portable/`へコピーし、.NETの探索先を存在しないフォルダーへ固定、新しい展開先とデータフォルダーで起動しました。同じ単体exeからの画面取得・入力用補助プロセス、画像対応実モデルによる作業、モデル準備中の画面を閉じる操作、対象応答停止中のキャンセルまで通っています。結果・描画は`artifacts/computer-use-portable/verification/`、同梱CPU / Vulkanの`llama-server.exe`と`sd-cli.exe`全4つの展開・起動結果は`artifacts/computer-use-portable/native-check.json`です。

最終exeのSHA-256は`F905AA6B2CAFD81EB36F14F4C42398C751440BA54CA74553FCC1CFFC948AABEB`。配布用ネイティブの構成・固定コミットは変更せず、既存の一体構成・静的CRTビルドを同梱しました。

実IME変換、実機150%／200% DPI、複数モニター、スクリーンリーダー、Officeやブラウザーを含む各アプリ固有の操作、すべてのマウス操作の実機組み合わせ、他PC・GPUでの成功率は未確認です。自動検証の結果を全Windowsアプリでの動作確認として扱いません。
