# チャットから使うComputer Use

Computer Useを通常の会話へ統合しました。専用の操作ウィンドウはありません。ローカルモデルが作業計画を作り、許可したWindowsアプリを観察し、マウスとキーボードを自動で操作します。アプリの種類は固定していません。

## 始める

入力欄の作業モードで「Computer Use」を選んで依頼するか、通常チャットで次のように送ります。「＋」のComputer Useも作業モードを切り替えます。使用モデルはチャット左上で選びます。

```text
@Computer メモ帳に今日の作業リストを入力して。
```

`/computer`や「PCを操作して…」という明示的な依頼にも対応します。Computer Useについて質問しただけでは操作を始めません。

回答にアプリの一覧が表示されます。対象を1〜8個選び、「許可して続行」を押します。初期設定は「マウス・キーボードを自動操作」です。文字入力、入力欄の選択、通常のクリック、キー操作、スクロール、ドラッグ、許可した対象の切り替えは、各操作の確認を省略して進めます。自動操作をオフにすると各操作を確認します。モデルが別のアプリを必要とした場合は、同じカードで追加の許可を求めます。

アプリが開いていない場合は、カードの「アプリを起動する」でWindowsのスタートメニューに登録されたアプリを選んで起動し、一覧を更新します。起動は利用者のボタン操作で行います。モデルの文字列を実行ファイルのパスやコマンドとして実行しません。登録されていないexeやダウンロードしたファイルを直接指定して起動する機能はありません。

画像対応GGUFと対応するprojectorを設定すると、画像とUI要素を併用します。projectorなしではUI要素を指定する操作を使い、座標だけの操作とドラッグは利用できません。アプリによってUI要素の取得状況は異なります。

## 作業中と追加指示

会話内のカードには、計画、進捗、最後に取得した画面、重要な操作の確認、操作履歴を表示します。実行中はプレビューを表示し、完了後は折りたたみます。画像は常時配信ではなく、操作の判断に使った最新の取得画像です。

- 「一時停止」は判断中の生成や補助プロセスも中断し、再開を待ちます。
- 「自分で操作」は制御を利用者へ返します。認証や独自の画面操作を済ませ、「最新画面から再開」を押します。
- 同じ会話で追加の指示を送ると、現在の操作案を中断してから新しい指示を反映します。実行済みの操作は再送せず、最新画面を取得します。
- 「停止」、入力欄の■、Ctrl+Alt+Escは作業を終了します。実行済みの入力・保存は取り消しません。

チャットやプロジェクトを切り替えても作業は続きます。「処理リスト」で状態を確認し、元の会話へ戻る・停止する操作ができます。デスクトップ操作は1件ずつ実行し、別のComputer Useは順番を待ちます。一時停止中は操作枠とモデルを解放します。通常チャットとは独立した推論プロセスを使うため、同時利用には追加のRAM／VRAMが必要です。

Windowsでは同じデスクトップのマウスとキーボードを共有します。対象アプリは表示したままにし、手動操作を行う前に一時停止してください。アプリ全体を終了すると進行中の作業を中断します。

## 確認と対象範囲

通常操作の自動実行と、重要な操作の確認は分けています。モデルが重要と判断した案に加え、送信・購入・支払い・削除・公開・上書き・権限等を示すボタン名、確定・削除・保存等のキーはローカルの規則でも確認します。Ctrl+V/XによるOSクリップボードの貼り付け・切り取りも確認します。確認時は対象画面、操作、入力文字を表示し、入力文字を修正できます。「実行せず停止」では入力しません。

この判定は、どのアプリでも重要な操作を完全に識別する保証ではありません。独自のアイコン、キャンバス画面、一般的な「OK」等の意味をモデルが誤読する可能性があります。重要な作業では自動操作をオフにし、結果を対象アプリでも確認してください。

画面内の命令は観察データとして扱い、操作の許可を拡張する根拠にしません。対象のプロセスID・開始時刻・ウィンドウ、所有ポップアップ、位置、UI要素、画像の変化を入力直前に再確認します。確認後に画面が変わった案は実行せず考え直し、3回連続で変化した場合は利用者へ引き継ぎます。

モデルには現在の依頼、同じ会話の直近の本文、通常のナレッジ規則で選んだ抜粋、対象画面、最近の操作を渡します。プロジェクト限定メモリの境界を維持し、別プロジェクトの資料を参照しません。採用した資料は回答の「渡したナレッジ」から確認できます。長い会話・資料や古い追加指示は予算内へ切り詰め、最新の追加指示を優先します。スキルの補助コードはこの経路では実行しません。

認証・パスワード・CAPTCHA・購入／支払い・保護画面・端末／コマンド実行は、モデルへの指示で利用者へ引き継ぎます。UI Automationがパスワードと報告した欄は画像と本文をマスクし、操作しません。属性を公開しない独自の秘密情報や、画面へ平文で表示された情報は自動では検出できません。WindowsキーやAlt+Tab等の対象外へ移るキーは拒否します。

## 履歴と再開

依頼、追加指示、計画、操作内容、入力した文字、理由、結果、モデルの完了報告を会話へ保存します。履歴JSONと全体バックアップにも含みます。スクリーンショット、対象アプリのハンドル、アプリの操作許可は保存しません。

再起動後の未完了の作業は「再開できます」と表示し、自動で操作しません。再開を選んだ場合もアプリを再選択・許可し、最新画面を取得します。保存した操作は再送しません。会話の所属プロジェクトが変更された場合は再開せず、その範囲から新しく依頼します。

初期の操作上限は100回、実行時間は合計20分までです。一時停止時間は実行時間に含めず、再開しても実行済みの回数と時間を引き継ぎます。依頼・追加指示は各4,000文字、追加指示は40回までです。UI要素は最大256件、探索は640要素・深さ16まで、画像は長辺1,280pxまでです。取得・入力の補助プロセスは1要求12秒で打ち切ります。

## ChatGPTとの比較と検証

ChatGPTの[公式Computer Useの説明](https://learn.chatgpt.com/docs/computer-use)を、会話からの依頼、アプリ単位の許可、自動操作、進捗表示、利用者への引き継ぎの参考にしました。Elunaはllama.cppとWindows標準APIで実装しており、ChatGPTのモデル・ブラウザー基盤・プラグインを内蔵したものではありません。使用するモデルの視覚理解・判断力によって成功率と速度が変わるため、ChatGPTと同等の操作精度が実証されたとは説明しません。

開発ビルドではQwen3.5-4B Q4_K_M＋projector、RX 9070 XT／Vulkanで、チャットからの開始、アプリ許可、確認を挟まない日本語入力・保存ボタンのクリック、保存済み表示の確認、一時停止・追加指示・会話切り替え・再開、履歴保存、停止キー、対象が応答停止した場合の中断を確認しています。専用の検証アプリ以外の利用者データは操作していません。

`./scripts/Verify.ps1`には操作形式、通常操作の自動実行と重要操作の確認、キーの別名、アプリ追加の許可、確認拒否、再開時の再送防止、保存状態、不正な起動パス、キャンセル、排他の検証を含めます。実機の検証コマンドは次のとおりです。

```powershell
Eluna.exe --verify-computer <結果フォルダー> --data-dir <空の検証用データフォルダー> --model-meta <画像対応モデルのmodel.json>
```

実IME、スクリーンリーダー、実機高DPI・複数モニター、Office／ブラウザー等の各アプリ固有の操作、すべてのドラッグ・クリップボード操作、スタートメニューからの各アプリ起動、他PC／GPUの成功率は未確認です。OSの権限制約、最小化、動くUI、画像取得制限により停止する場合があります。OSによる隔離やロールバックはありません。

2026-10-16の配布確認は`artifacts/release-computer-chat/Eluna.exe`を単独でコピーし、インストール済み.NETの探索先を存在しないフォルダーへ設定して実行しました。自動検証は`artifacts/computer-chat-verify.log`、配布ログは`artifacts/computer-chat-publish.log`、実モデル・会話内の許可と確認拒否・描画・中断の結果は`artifacts/computer-chat-portable/verified-release/verification.json`と同フォルダーのPNGです。同梱CPU / Vulkanの推論・画像生成エンジン全4つの展開と起動は`artifacts/computer-chat-portable/native-release.json`に記録しました。最終exeのSHA-256は`9E498697B6B90077F58BCCC91B103E0A1746FFD40DC12FB3B5FF29A630F8E93F`です。

実モデルでは、正しい結果が表示された後もクリックや保存を重ねる例を観測しました。操作済みの状態を読む指示を追加していますが、反復が完全に解消されたとは扱いません。起動一覧はスタートメニューの`.lnk`が対象で、ストアアプリ等を網羅しません。対象アプリを通常の方法で開いた後の操作許可も利用できます。
