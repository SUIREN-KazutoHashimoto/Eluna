# プロジェクトとナレッジの仕様

## 参照する情報

会話をまとめるプロジェクトに、専用の指示・資料・保存メモリを持たせる。初期設定は「プロジェクト限定」。プロジェクト外の会話・資料・保存メモリと共通のカスタム指示を参照しない。プロジェクトのない通常チャットでは、共通指示・共通の保存メモリと現在の会話を使う。

作成時に「共通メモリも使う」を選んだプロジェクトは、共通指示・共通の保存メモリも利用する。他プロジェクトの情報や通常チャットの履歴を自動で探すことはない。範囲は作成時に固定し、画面に表示する。プロジェクトの指示と会話別の指示を共通指示より優先する。

モデル・思考量・表示・検索上限・ディベートの参加者設定はアプリ共通。ディベートの役割指示は実行する役割の指定として適用する。プロジェクト固有の事実・前提を保存する場所は、プロジェクトの指示・資料・保存メモリとする。

| 情報 | 保存・更新 | 使われる範囲 |
| --- | --- | --- |
| 会話履歴・添付 | 会話の送受信・ファイル添付 | その会話。別会話への参照は同じプロジェクトだけ |
| 引き継ぎメモ | 長い会話を自動要約、手動編集可能 | その会話の分岐だけ。永続メモリとは別 |
| 保存メモリ | 利用者が追加・編集・削除。回答から保存するときも内容を確認する | 保存先のプロジェクト、または共通メモリを使う範囲 |
| ナレッジ資料 | ファイルから読み取った本文のコピーを登録。元ファイルは変更しない | 登録したプロジェクトだけ |
| 同じプロジェクトの別会話 | 参照を有効にした場合に質問に関連する部分を抽出 | 同じプロジェクトの、保管されていない会話の現在の分岐。下書きは対象外 |

AIが会話から無断で保存メモリを追加・変更する処理は設けない。メモリの管理は設定またはプロジェクトの管理画面から行う。

## 資料の読み取りと検索

TXT / Markdown / CSV / JSON / LOGとDOCX / XLSX / PPTXを標準機能で読み取る。1ファイル32 MBまで、本文は先頭60,000文字まで。画像とPDFは画像対応GGUFと同系列のprojectorで本文を読み取り、PDFは6ページまで。画像による読み取りは誤認識を含むため、登録後は無効状態とし、利用者が本文を確認・修正して参照を有効にする。資料は64件、保存メモリは各保存先100件・1件4,000文字まで。

検索は.NET標準機能による文字列検索。日本語の部分一致・英数字の語句と資料名を使って順位を付ける。埋め込みモデル、ベクトルDB、外部検索APIは導入しない。別会話は同じプロジェクトの直近200件・各会話末尾20発言とその添付を候補にする。質問に関連する抜粋を入力長に合わせて最大8件・各700文字まで渡し、すべての資料を毎回読む機能とはしない。該当しない情報や入力枠に収まらない情報は渡さない。

AIへ渡した抜粋を回答ごとに保持し、画面から出所・内容を確認できるようにする。調査を再開すると現在の資料・メモリで再検索し、抜粋の表示も最後の再開時のものへ更新する。過去の工程・計画・途中の回答には以前の情報が残る。ローカル資料の識別子は`[K1]`など、Web資料は従来の`[S1]`などで区別する。抜粋が渡されたことと、回答が根拠を正しく使ったことは別であり、意味の正しさを自動保証するものではない。資料内の命令文は利用者の指示として扱わない。

通常回答、深掘り調査・ディベート、文書生成で同じ参照範囲を適用する。Web検索は従来どおり「自動／必ず／検索しない」を選べる。検索・調査では、質問や資料に由来する検索語を外部へ送信する場合がある。プロジェクト限定メモリは参照範囲の制御であり、オフライン設定とは別。

画像・文書生成画面は開いたプロジェクトに所属する。チャット側で別プロジェクトへ切り替えた場合は生成や会話への添付を実行せず、元のプロジェクトへ戻すか画面を開き直すよう案内する。既存本文の編集・プレビュー・ファイルへの保存は続けられる。文書の編集中の下書きもプロジェクトごとの別ファイルへ保存し、共通の下書きを流用しない。生成物や下書きをナレッジへ自動登録することはない。

## 移動・削除・保存

既存チャットは確認後に所属を移動できる。会話本文・添付・下書き・会話別の指示・生成時の参照記録は移動対象、プロジェクトの資料・保存メモリは対象外。移動時は会話の要約を破棄して再計算し、以前の調査の再開を無効にする。本文などには以前の情報が残るため、移動先へその内容を持ち込むことを確認画面で明示する。

資料・メモリを削除または無効にすると、以後の新しい参照対象から外す。過去の会話本文、回答に保存した抜粋、調査の途中記録、バックアップには内容が残り得る。プロジェクトの削除は、そのプロジェクトの会話・資料・保存メモリも削除する確認操作とする。バックアップの自動消去やディスク上の完全消去は意味しない。

推論予約は送信時の指示とナレッジ抜粋を保持する。予約後の資料・メモリの変更は新しい依頼から反映するため、既存の予約からも除きたい場合はその予約をキャンセルして送信し直す。予約がある会話の移動・削除や、その会話を含むプロジェクトの削除は先に予約を終了させる。参照内容の固定と再起動時の扱いは[並行作業ガイド](concurrent-work.md)を参照。

会話・所属・プロジェクトの指示・登録資料・保存メモリはローカルの既存保存データ・世代バックアップへ含める。旧データには所属なし・メモリなしとして対応する。履歴の取り込みではプロジェクトIDを新しく割り当て、既存プロジェクトと混ざらないようにする。共通メモリの取り込みは明示的に選ぶ。バックアップの復元はその時点のプロジェクト・メモリも含めて復元する。生成文書の下書き・書き出した生成物・元のファイルは別管理で、履歴JSONへの取り込み・バックアップ・プロジェクト削除の対象には含めない。OSの別利用者から保護する暗号化・アクセス制御を追加する機能ではない。

初めてプロジェクトまたは保存メモリを保存した時点で、履歴を形式2の`state-knowledge.json`へ移行する。旧版が使う`state.json`は変更せず残し、旧版がプロジェクトの所属や資料を落として新形式のデータを上書きすることを防ぐ。以降は新形式を優先する。移行後に旧版で行った変更は自動で合流しないため、必要なら旧版から書き出して取り込む。新形式の履歴JSONは旧版への取り込み対象としない。

スキルを利用して形式3へ移行した場合は、会話・ナレッジも`state-skills.json`を優先して保存する。従来の両ファイルは保持する。スキルの資料・補助コード出力を回答で使った場合、その主な抜粋も既存の8件の参照枠へ含め、詳細は使用スキル画面へ保存する。形式と互換範囲は[スキルガイド](skills.md)を参照。
